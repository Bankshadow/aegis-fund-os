# E57 — S003 บนเอนจินของคนอื่น: ผลของเราเป็นของจริง หรือเป็นของโค้ดเรา (ประกาศก่อนรัน)

> **สถานะ: DECLARED — ยังไม่รัน** (2026-08-16)
> เขียนเสร็จ **ก่อน** แตะรันเนอร์ · ห้ามแก้หลังเห็นผล

## 0. คำถาม และสิ่งที่ E57 **ไม่ได้** ทดสอบ

E51 ตรวจแล้วว่าผลไม่เสถียรข้าม **แหล่งข้อมูล** · E50/E56 ตรวจแล้วว่าผลไวต่อ
**สมมติฐาน fill** · แต่ **เอนจินที่รันทุกการทดลองตั้งแต่ E44 คือโค้ดที่เราเขียนเอง
ตัวเดียว และไม่เคยถูกตรวจสอบข้ามการ implement เลย**

> **คำถามของ E57: ถ้ารัน S003 บนเอนจิน backtest ที่คนอื่นเขียน
> (`backtrader`, GPL-3.0) portR ยังตกอยู่ในช่วง `[+43.76, +72.81] R` ที่ E56
> ประกาศไว้หรือไม่**

**สิ่งที่ E57 ทดสอบจริง**: การวนแท่ง, ลำดับการจับคู่คำสั่ง, กลไก fill,
การตัดบัญชี, และการคิดค่าธรรมเนียม — ทั้งหมดนี้เป็นของ backtrader ไม่ใช่ของเรา
นี่คือจุดที่บั๊กเงียบ ๆ มักซ่อนอยู่

**สิ่งที่ E57 ทดสอบไม่ได้ และต้องระบุทุกครั้งที่อ้างผล**: กฎสัญญาณ / stop /
target ถูก**เข้ารหัสใหม่โดยผู้เขียนคนเดิม** ถ้าเราอ่านสเปกผิดตั้งแต่ต้น E57
จะอ่านผิดซ้ำแบบเดียวกันและยืนยันความผิดนั้น → **นี่คือ implementation
independence ไม่ใช่ specification independence**

**เงื่อนไขลิขสิทธิ์ (บังคับ)**: `backtrader` เป็น **GPL-3.0** · ติดตั้งใน venv
ใน scratchpad **นอกรีโป** · **ห้าม vendor โค้ดเข้ารีโป ห้าม import จากโค้ดในรีโป
ห้ามแจกจ่ายผลที่ derive จากมัน** · รันเนอร์ E57 อยู่นอกรีโปด้วย สิ่งที่เข้ารีโป
มีแค่ **ตัวเลขผลลัพธ์** และเอกสารนี้

## 1. การตั้งค่าที่ล็อกก่อนรัน

| รายการ | ค่า | เหตุผล |
|---|---|---|
| ข้อมูล | `data/s003/{SOL,LINK}-USD_full.json` ชุดเดียวกับ E45–E56 | ต้องเปลี่ยนตัวแปรเดียว คือเอนจิน |
| เข้าไม้ | `broker.set_coc(True)` (cheat-on-close) | สเปกเข้าที่ **ราคาปิดของแท่งสัญญาณ** |
| ATR | **ของ backtrader เอง** (`bt.ind.ATR`, Wilder) ไม่ใช่ของเรา | ความเป็นอิสระสูงสุด |
| ค่าธรรมเนียม | 0.05%/ข้าง | ช่องอ้างอิงของ E56 |
| ขนาดไม้ | 1 หน่วยคงที่ | portR ไม่ขึ้นกับขนาด |
| warmup | 201 แท่ง | เหมือนสเปก |
| ลำดับคำสั่งในแท่งที่ชนทั้ง TP3 และ stop | **รันทั้งสองแบบ** (ส่ง TP ก่อน / ส่ง stop ก่อน) | นี่คือแกน `tp_first`/`sl_first` ในภาษาของ backtrader |

**คำทำนายที่บันทึกไว้ก่อนรัน (จะถูกหรือผิดก็ต้องรายงาน)**: backtrader เรียก
`next()` **หลังแท่งปิด** จึงเลื่อน stop มา BE ได้เร็วที่สุดคือแท่งถัดไป
⇒ **มันจะสร้างกฎ "แท่งที่ arm BE ไม่โดน stop" ขึ้นมาเองโดยอัตโนมัติ**
ถ้าจริง แปลว่ากฎที่ `final_logic.md` ลืมเขียน (E55 D) คือ**พฤติกรรมปกติของ
backtester แบบ event-driven** ไม่ใช่สมมติฐานที่เราแอบใส่เข้าไป

## 2. เกณฑ์ (ประกาศก่อนเห็นผลทุกตัว)

| id | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| **R0** | **ATR ตรงกันก่อน**: ATR ของ backtrader เทียบของเรา ทุกแท่งหลัง warmup | ค่าเบี่ยงเบนสัมพัทธ์สูงสุด ≤ **0.5%** · **ไม่ผ่าน = หยุด** (ต่างที่ ATR ทำให้ทุกอย่างหลังจากนั้นเทียบไม่ได้) |
| **R1** | **คำถามหลัก**: portR ของ backtrader **ทั้งสองลำดับคำสั่ง** ตกอยู่ใน `[+43.76, +72.81]` | อยู่ในช่วงทั้งคู่ |
| **R2** | ลำดับ TP-ก่อน เทียบ `tp_first` ของเรา (+72.81) และ stop-ก่อน เทียบ `sl_first` (+43.76) | ต่างจากปลายที่คู่กัน ≤ **10%** |
| **R3** | **วันเข้าไม้ตรงกัน**: สัญญาณเป็นฟังก์ชันล้วนของ OHLC+ATR จึงไม่ควรขึ้นกับเอนจิน | ≥ **98%** ของไม้ backtrader มีวันเข้าตรงกับไม้ของเรา |
| **R4** | **เหตุผลออกตรงกัน** บนไม้ที่จับคู่ได้ (TP3 / SL / BE_SL / EOD) | ≥ **80%** |
| **R5** | **คำทำนายข้อ §1**: มีไม้ไหนถูก stop ที่ BE ในแท่งเดียวกับที่ arm ไหม | **รายงาน** — ยืนยันหรือหักล้างคำทำนาย |
| **R6** | **โมเดลค่าธรรมเนียม**: สูตรของเรา (คิดสองขาบนราคา**เข้า**) เทียบค่าจริงของ backtrader (คิดตาม notional จริงแต่ละขา) | **รายงาน** เป็น R — นี่คือ approximation ที่ audit ระบุไว้ ในที่สุดก็ได้วัด |
| **R7** | **ต่อเหรียญ** SOL / LINK | **รายงาน** |

**จำนวนไม้**: รายงานเสมอ แต่ **ไม่ใช่เกณฑ์** — ไม้ที่ถูกปัดด้วย `R > 3 ATR`
อาจต่างกันได้ตามความละเอียดของ ATR

## 3. ตารางการตัดสินใจ

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| R0–R2 ผ่าน | ช่วง `[+43.76, +72.81]` **ทนการเปลี่ยนเอนจิน** | เป็นหลักฐานที่แข็งที่สุดที่ S003 มี · บันทึกและหยุด |
| **portR ต่ำกว่าช่วงมาก** | อาจมี**บั๊กเงียบในเอนจินของเรา**ที่เข้าข้างตัวเอง | **หยุดทุกอย่าง สอบสวนเอนจินก่อน** · ผล E44–E56 ทั้งหมดถูกแขวนไว้จนกว่าจะรู้สาเหตุ |
| portR สูงกว่าช่วงมาก | เอนจินของ backtrader ใจดีกว่า หรือ map กฎไม่ตรง | ตรวจ mapping ก่อนสรุป · ห้ามรายงานเป็น "ผลดีกว่า" |
| R3 ตก | เข้าไม้คนละชุด → เทียบ portR ไม่มีความหมาย | **ซ่อม mapping ก่อน แล้วรันใหม่** · ห้ามอ่าน R1/R2 |
| R4 ตก แต่ R1/R2 ผ่าน | ออกไม้ต่างทางแต่ผลรวมเท่ากัน = การหักล้างกันโดยบังเอิญ | ระบุเป็นข้อสงสัย ไม่ใช่ผ่าน |
| R5 ยืนยันคำทำนาย | กฎ BE-arming-bar เป็นมาตรฐาน ไม่ใช่ของแถม | อัปเดต `final_logic.md` §4 ให้ระบุที่มา |
| R6 ต่างกันมาก | สูตร fee ของเราเข้าข้างตัวเอง | ระบุขนาดผลกระทบเป็น R ในทุกการรายงานต่อจากนี้ |

## 4. สิ่งที่จะไม่ทำ

- **ไม่แก้กฎในเอนจินของเราเพื่อให้ตรงกับ backtrader** และไม่แก้ทางกลับกัน —
  ถ้าไม่ตรง นั่นคือผลลัพธ์ ไม่ใช่บั๊กที่ต้องกลบ
- **ไม่ปรับ tolerance หลังเห็นผล** — 0.5% / 10% / 98% / 80% ล็อกแล้วในเอกสารนี้
- ไม่ vendor โค้ด GPL เข้ารีโป · ไม่เพิ่ม dependency ให้ `gate/verify.ps1`
  · ไม่เพิ่ม host ใน egress allowlist (ไม่มีการดึงข้อมูลออนไลน์ ใช้ไฟล์ในรีโป)
- ไม่แตะ strategy library 20+ ตัวของ `ai-trader` (E54: ผู้สมัคร 10 ตัวไม่รอดสักตัว
  การเพิ่มผู้สมัครคือการเพิ่ม multiple testing ไม่ใช่การเพิ่ม edge)
- ไม่ใช้ MCP server ของโปรเจกต์นั้น — การทำให้ backtest ถูกลงขัดกับกฎ
  "ประกาศเกณฑ์ก่อนรัน" โดยตรง (E53/E54/E55 A4 วัดราคาของการค้นหาแบบถูก ๆ แล้ว)
- ไม่อ้างว่า E57 = specification independence · ไม่ promote · ไม่มีคำสั่งจริง
