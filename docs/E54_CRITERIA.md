# E54 — คัดกลยุทธ์จากผู้สมัครหลายตัวพร้อมกัน โดยไม่ให้จำนวนผู้สมัครสร้างผู้ชนะปลอม (ประกาศก่อนรู้ว่าผู้สมัครคืออะไร)

> **สถานะ: DECLARED — ยังไม่มีผู้สมัครแม้แต่ตัวเดียว** (2026-08-15)
> เขียนเสร็จ **ก่อน** เรียก agent · **ก่อน**รู้ว่าจะมีกลยุทธ์อะไรบ้าง
> ห้ามแก้หลังเห็นผู้สมัครหรือผลลัพธ์ · จองเลขใน `docs/EXPERIMENT_REGISTRY.md` แล้ว

## 0. คำขอ และปัญหาที่ต้องแก้ก่อนเริ่ม

ผู้ใช้ขอ **"หา agent เก่งเฉพาะด้าน 10 ตัวมาช่วย ต้องได้กลยุทธ์ที่ดีที่สุด"**

**ปัญหาเชิงสถิติที่มาพร้อมคำขอนี้**: ถ้าทดสอบผู้สมัคร N ตัวแล้วเลือกตัวที่ดีที่สุด
ผู้ชนะจะดูดีแม้ทุกตัวไม่มี edge เลย · ที่ N = 10–20 นี่ไม่ใช่ความเสี่ยงเล็ก ๆ
มันคือผลลัพธ์ที่คาดหมายได้ · ledger นี้บันทึกความผิดพลาดแบบนี้ไว้ 4 ครั้ง
(E46, E48 W1, E53 P2, C7)

**วิธีแก้ที่ล็อกไว้ตรงนี้ ก่อนเห็นผู้สมัคร**:

1. **agent ส่งสเปก ไม่ส่งตัวเลข** — ทุกผู้สมัครถูก implement ใหม่ใน harness
   เดียวกันโดยผู้เขียนคนเดียว · ตัวเลขจาก agent ไม่ถูกใช้เป็นหลักฐาน
   (ถ้า agent ส่งตัวเลขมา จะถูกบันทึกว่าเป็นคำกล่าวอ้าง ไม่ใช่ผล)
2. **placebo แบบ max-statistic** — เกณฑ์ผ่านไม่ใช่ "ชนะ placebo ของตัวเอง"
   แต่ **"ชนะ placebo ที่ดีที่สุดในบรรดา placebo ทั้งหมดของผู้สมัครทุกตัว"**
   ยิ่งผู้สมัครเยอะ เพดานยิ่งสูงขึ้นเอง ตามที่ควรเป็น
3. **ด่านทั้งหมดประกาศไว้ที่นี่** ก่อนรู้ว่าผู้สมัครคืออะไร

> **คำถามของ E54: มีกลยุทธ์ไหนรอดด่านทั้งหมดพร้อมกัน โดยที่เพดานถูกยกให้
> สูงตามจำนวนผู้สมัครแล้ว**

**คำตอบที่ยอมรับได้และน่าจะเป็นที่สุดคือ "ไม่มี"** — และถ้าเป็นเช่นนั้น จะรายงาน
ตรง ๆ ว่าไม่มี ไม่ใช่ยกตัวที่ดีที่สุดของรอบขึ้นมาเป็นผู้ชนะ

## 1. ข้อกำหนดของผู้สมัคร (ล็อกก่อนเรียก agent)

- ใช้ได้เฉพาะ **daily OHLCV ของ 33 เหรียญใน `data/universe/spot_1d.json`**
  และ **funding รายวันใน `data/universe/funding_daily.json`**
- **gross exposure ≤ 1.0 ไม่มี leverage** · rebalance ไม่ถี่กว่าทุก 1 วัน
- ต้องมี **กลไกที่อธิบายได้** ไม่ใช่รูปแบบที่เจอจากการค้น
- ต้องระบุ **พารามิเตอร์หลัก 1 ตัว พร้อมค่ากลางและเพื่อนบ้านสองข้าง**
  (ใช้ในด่าน G5) · ผู้เขียนสเปกเป็นคนระบุ ไม่ใช่เลือกทีหลัง
- ผู้สมัครที่ตัดสินด้วย **การเปรียบเทียบไม่ต่อเนื่อง** (เช่น `high > high[1]`)
  รับได้ แต่จะถูกวัดด้วย G2 เหมือนกันหมด (S003 ตายตรงนี้)

## 2. ด่าน (ทุกผู้สมัครเจอชุดเดียวกัน)

| id | ด่าน | ผ่านเมื่อ |
|---|---|---|
| **G1** | **harness**: รัน M1-LS (k30/v20/r7, 0.15%, ไม่มี funding) ต้องได้ +71.5% / DD 50.9% ตาม E52 | ต่าง ≤ 0.5 จุด · **ไม่ผ่าน = หยุดทั้งหมด** |
| **G2** | **noise ระดับ vendor** — สุ่มจากส่วนต่าง Yahoo−Binance จริง · 20 seeds | **≥18/20 เครื่องหมายเดิม** และ **มัธยฐาน ≥ 70% ของผลสะอาด** |
| **G3** | **ครึ่งแรก/ครึ่งหลัง** (แบ่งกลางเวลา) | **บวกทั้งสองครึ่ง** |
| **G4** | **ต้นทุนจริง**: 0.15%/ข้าง **+ funding จริง** | ผลตอบแทนรวมยังบวก |
| **G5** | **ไม่ใช่ยอดแหลม** (บทเรียน E53): พารามิเตอร์หลักที่เพื่อนบ้านสองข้าง ต้องได้ **ret/DD ≥ 60% ของค่ากลาง ทั้งสองข้าง** | ทั้งสองข้าง |
| **G6** | **placebo max-statistic**: ทุกผู้สมัครถูกจับคู่กับ placebo ที่ **turnover และ gross เท่ากันแต่สัญญาณสุ่ม** 20 seeds · ผู้สมัครต้องชนะ **ค่าสูงสุดของ placebo ทั้งหมดจากผู้สมัครทุกตัวรวมกัน** | > max |
| **G7** | **walk-forward พารามิเตอร์คงที่**: train 730 → test 182 เลื่อน 182 · ต่อ OOS · ต้องบวก | > 0 |
| G8 | ตารางผู้สมัครทุกตัว ทุกด่าน | **รายงานเสมอ ไม่ตัดตัวที่แพ้ออก** |

**"กลยุทธ์รอด" = G2–G7 ผ่านครบ** · ตกด่านเดียว = ไม่รอด ไม่มีการถ่วงน้ำหนัก

**เกณฑ์เทียบทุกตาราง**: EW buy&hold, BTC buy&hold, และ M1-LS (challenger ปัจจุบัน)

## 3. ตารางการตัดสินใจ (เขียนก่อนเห็นผู้สมัคร)

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| มีผู้รอด 1 ตัว | รอดด่านที่ฆ่าทุกตัวก่อนหน้า **และ**เพดานถูกยกตามจำนวนผู้สมัครแล้ว | บันทึกเป็น challenger ร่วม · **ยังไม่ promote** · ขั้นต่อไป execution/slippage |
| มีผู้รอด > 1 ตัว | **ห้ามเลือกตัวที่ดีที่สุด** | รายงานทั้งหมดเป็นผู้รอดเท่ากัน · การรวมพอร์ตเป็นการทดลองแยก |
| **ไม่มีผู้รอด** | **10 agent ไม่ได้ผลิตกลยุทธ์ที่รอด** | **รายงานว่าไม่มี** · บันทึกว่าการเพิ่มจำนวนผู้ค้นไม่ได้เพิ่มโอกาสพบ edge |
| ผู้รอดตก G6 อย่างเดียว | ดีพอ ๆ กับ placebo ที่ดีที่สุด | **ไม่ใช่ผู้รอด** — นี่คือจุดที่ N ตัวสร้างผู้ชนะปลอม |
| ทุกตัวตก G5 | ทุกตัวเป็นยอดแหลม | **ข้อค้นพบหลัก**: การค้นหาผลิต overfit ไม่ใช่กลไก |
| G1 ตก | harness เพี้ยน | **หยุด สอบสวนก่อน** |

## 4. สิ่งที่จะไม่ทำ

- **ไม่ใช้ตัวเลขที่ agent รายงานเป็นหลักฐาน** — implement ใหม่ทุกตัวเสมอ
- **ไม่เลือกผู้ชนะจากผู้สมัครที่ตกด่าน** ต่อให้ตัวเลขดูดีที่สุดในรอบ
- ไม่กวาดพารามิเตอร์ของผู้สมัคร (ใช้ค่ากลางที่สเปกระบุ + เพื่อนบ้านสำหรับ G5 เท่านั้น)
- ไม่เพิ่มผู้สมัครหลังเห็นผลของชุดแรก · ไม่รันซ้ำด้วย seed ใหม่ถ้าผลไม่ถูกใจ
- ไม่ใช้ leverage · ไม่ลดเกณฑ์ ValidationGate · ไม่ promote
- ไม่มีคำสั่งจริง ไม่มีคำแนะนำการลงทุนรายบุคคล
