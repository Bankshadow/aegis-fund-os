# E47 — sizing overlay ลด drawdown ของ S003 ได้จริงไหม เทียบกับ "แค่ลดขนาดไม้" (ประกาศก่อนรัน)

> **สถานะ: DECLARED — ยังไม่รัน** (2026-08-12)
> เขียนเสร็จ **ก่อน** แตะโค้ดแม้แต่บรรทัดเดียว ห้ามแก้หลังเห็นผล
> จองเลขใน `docs/EXPERIMENT_REGISTRY.md` แล้ว

## 0. คำถาม และเหตุผลที่ต้องตั้งแบบนี้

ที่เสี่ยง 6%/ไม้ S003 ได้ CAGR +37.2% แต่ **maxDD 72.1%** · ผู้ใช้ต้องการ
"ยอมกำไรน้อยลงเพื่อรักษาพอร์ต"

**การวัดก่อนหน้าบอกว่ารูปแบบความเสียหายคืออะไร**: DD 72% เกิดจาก **30 เทรดใน
7.3 เดือน (แพ้ 28 ชนะ 2)** ไม้แย่สุดคิดเป็นแค่ **5.3%** ของความเสียหาย และ
**ทั้งชุด 339 เทรดไม่มีไม้ไหนแย่กว่า −1.04 R** → **เป็นการกัดกร่อนสะสม
ไม่ใช่ระเบิดลูกเดียว** ดังนั้นเครื่องมือที่กัน tail (เช่น option) ไม่ตรงกับปัญหา
และเราไม่มีข้อมูลราคา option จึงทดสอบไม่ได้อยู่แล้ว

**กับดักหลักของการทดลองนี้**: overlay ทุกตัว "ลด DD" ได้ทั้งนั้นถ้ามันทำให้ถือ
น้อยลงโดยเฉลี่ย — นั่นไม่ใช่ความสามารถ **การเทียบที่ยุติธรรมคือเทียบที่ DD เท่ากัน**

> **คำถามเดียวของ E47: ที่งบ drawdown เท่ากัน overlay ให้ผลตอบแทนมากกว่า
> การลดขนาดไม้เฉย ๆ หรือไม่**

ถ้าไม่ → **คำแนะนำคือลดขนาดไม้ จบ** ไม่ต้องเพิ่มความซับซ้อน

## 1. วิธีทำให้เทียบกันได้ (ล็อกก่อนรัน)

1. ทุกแขน **ปรับ `base_risk` ด้วย binary search ให้ maxDD บนช่วง IS ≈ 45%**
   (±1 จุด) — 45% เลือกเพราะเป็นค่ากลางระหว่าง 6% (72%) กับ 3% (46%) ที่วัดไว้แล้ว
   **ไม่ได้เลือกจากผล**
2. นำ `base_risk` ที่ปรับได้ **ไปใช้กับ OOS โดยไม่ปรับซ้ำ** — ถ้า DD บน OOS
   หลุดไปมาก นั่นคือข้อมูล ไม่ใช่ข้อบกพร่อง
3. **เกณฑ์ตัดสินอ่านจาก OOS เท่านั้น**

**IS** = เข้าไม้ 2017-11-09 → 2022-08-01 · **OOS** = 2022-08-01 → 2026-08-13
(ช่วงเดียวกับ E46 ไม่ขยับ)

## 2. แขนที่ทดสอบ (ประกาศครบ ห้ามเพิ่มหลังเห็นผล)

**ทุกแขนเป็น sizing overlay เท่านั้น — ไม่แตะ entry/exit ตามสเปก §6**
(*"Optional sizing overlay only (not entry replace)"*)

| id | กฎการปรับขนาด |
|---|---|
| **V0** | **คงที่ = `base_risk` ทุกไม้ — control "แค่ลดขนาด"** |
| V1 | **vol-target ตามสเปก §6**: `scale = (σ_t/σ_ref)^(−0.5)`, clip [0.25, 2.0] · σ = ผันผวน 20 วันของเหรียญนั้น ณ วันเข้าไม้ · **σ_ref = มัธยฐานของ σ บนช่วง IS เท่านั้น** (คงที่ ไม่คำนวณใหม่บน OOS) |
| V2 | **เบรกเกอร์-3**: แพ้ติดกัน 3 ไม้ → ขนาดครึ่งเดียว จนกว่าจะชนะ 1 ไม้ |
| V3 | **เบรกเกอร์-5**: แพ้ติดกัน 5 ไม้ → ขนาดครึ่งเดียว จนกว่าจะชนะ 1 ไม้ |
| V4 | **equity-curve filter**: ถ้าทุน < ค่าเฉลี่ยเคลื่อนที่ 20 เทรดของตัวเอง → ขนาดครึ่งเดียว |
| V5 | **V1 + V3 รวมกัน — แขนผสมแขนเดียวที่ประกาศไว้** (คูณ scale ทั้งสอง) |

นับ "แพ้ติดกัน" ที่ระดับ**พอร์ต** เรียงตามวันปิดไม้ (ไม่ใช่แยกรายเหรียญ) —
เพราะสิ่งที่ต้องปกป้องคือบัญชี

**run count = 6 แขน × 2 ช่วง = 12** · ไม่มีการกวาดพารามิเตอร์
(3, 5, 20, γ=−0.5 เป็นค่ามาตรฐาน/มาจากสเปก ไม่ได้ fit)

## 3. เกณฑ์ตัดสิน

| id | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| **U1** | **แขนที่ดีที่สุดบน IS (CAGR) ชนะ V0 ด้วย CAGR บน OOS** | **> V0** |
| U2 | และ maxDD บน OOS ของแขนนั้น **ไม่แย่กว่า V0** | ≤ V0 |
| U3 | **มูลค่าของการเลือก**: แขนที่เลือกจาก IS ชนะ **มัธยฐาน** ของ V1–V5 บน OOS | ชนะ |
| U4 | การปรับ DD โอนไปยัง OOS ได้ไหม — รายงาน realized DD ทุกแขน | **รายงาน** |
| U5 | ตรวจ harness: V0 ที่ base_risk = 6% ต้องได้ DD 72.1% / CAGR +37.2% | ต่าง ≤ 0.5 จุด |

**"overlay คุ้ม" = U1 และ U2 ผ่าน** · ถ้า U1 ตก → **คำแนะนำคือลดขนาดไม้เฉย ๆ**

## 4. ตารางการตัดสินใจ (เขียนก่อนเห็นผล)

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| U1+U2 ผ่าน และ U3 ผ่าน | overlay เพิ่มค่าจริง และเลือกได้ | บันทึกเป็น challenger · **ยังไม่ promote** |
| U1+U2 ผ่าน แต่ U3 ตก | ได้แขนดีโดยบังเอิญ | ⚖️ การเลือกไม่ใช่สาเหตุ |
| **U1 ตก** | **ที่ DD เท่ากัน overlay ไม่ชนะการลดขนาดเฉย ๆ** | **คำแนะนำ: ลดขนาดไม้ จบ** — ความซับซ้อนไม่คุ้ม |
| U2 ตก แต่ U1 ผ่าน | ได้ผลตอบแทนแลกกับ DD ที่แย่ลง | ⚖️ ไม่ใช่การลดความเสี่ยง |
| DD บน OOS หลุดจาก 45% มาก ทุกแขน | การปรับขนาดจากอดีตไม่โอนไปอนาคต | **ข้อค้นพบสำคัญ — รายงานเด่น** |
| U5 ตก | harness เพี้ยน | **หยุด สอบสวนก่อน** |

## 5. สิ่งที่จะไม่ทำ

- **ไม่แตะ entry/exit/stop/target** — sizing overlay เท่านั้น (สเปก §6)
- ไม่กวาดค่า (ไม่ลอง breaker-2,4,6 หรือ γ อื่น) · ไม่เพิ่มแขนหลังเห็นผล
- ไม่ทดสอบ option — ไม่มีข้อมูลราคา และรูปแบบความเสียหายไม่ใช่ tail
- ไม่ใช้ตัวกรองจาก BTC — วัดแล้วว่าช่วง DD แย่สุด BTC **+131%** ตัวกรอง
  "BTC แข็ง = เสี่ยงมากขึ้น" จะเพิ่มขนาดผิดจังหวะพอดี
- ไม่รายงานเฉพาะแขนที่ดีที่สุด — **รายงานทั้ง 6 แขน ทั้งสองช่วง เสมอ**
- ไม่มีคำสั่งจริง ไม่มี promote
