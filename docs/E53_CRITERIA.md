## 0. คำขอ และการแปลเป็นการทดลองที่ตอบได้

ผู้ใช้ขอ **"เอา M1-LS มา optimize ต่อ"**

การส่งตารางพารามิเตอร์ที่ดีที่สุดบนข้อมูลทั้งหมดกลับไปคือสิ่งที่ ledger นี้
วัดแล้วสามครั้งว่าไร้ค่า (E46: variant อันดับ 1 บน IS ร่วงเป็นอันดับ 10 บน OOS ·
C7 20% vs 20% · E23–E25) **E53 จึง optimize จริงทุกขั้นตอน แต่ผลลัพธ์ที่รายงาน
คือ "กำไรที่ได้จริงจากการ optimize" ไม่ใช่ "ค่าที่ดีที่สุดที่หาเจอ"**

> **คำถามของ E53: การเลือกพารามิเตอร์จากอดีตแบบ walk-forward ให้ผลดีกว่า
> การตั้งค่าไว้เฉย ๆ หรือไม่ — และดีกว่าการสุ่มพารามิเตอร์หรือไม่**

E48 สอนไว้แล้วว่า **ถ้าไม่เทียบกับตัวสุ่ม จะแยกไม่ออกระหว่าง "เลือกเก่ง" กับ
"ทำอะไรก็ได้"** ด่านนั้นถูกใส่ไว้ตั้งแต่ต้นในครั้งนี้

## 1. ตารางพารามิเตอร์ (ประกาศครบ ห้ามเพิ่ม)

| แกน | ค่า |
|---|---|
| lookback `k` | 14, 21, **30**, 45, 60, 90 |
| vol window | 10, **20**, 40 |
| rebalance (วัน) | 3, **7**, 14 |

= **54 ชุด** · ตัวหนา = ค่าที่ E52 ประกาศเป็นค่าหลัก
**รวม k > 30 ซึ่ง E52 ไม่ได้ทดสอบ** เพราะการ optimize ต้องมีพื้นที่ให้ค้นจริง

**คงที่ทุกชุด ไม่แตะ**: logic = M1-LS, gross = 1.0 (ไม่มี leverage),
น้ำหนัก ∝ 1/σ, จักรวาล 33 เหรียญทั้งไฟล์

**ต้นทุนกรณีฐานของ E53 = 0.15%/ข้าง + funding จริง**
(`data/universe/funding_daily.json`, long จ่าย short รับ · ก่อน 2019-09-10 = 0)
E52 วัดแล้วว่า funding กิน 8 จุด CAGR — ปล่อยไว้ไม่ได้อีก

## 2. โครงสร้าง walk-forward (ล็อกก่อนรัน)

- **train 730 วัน → test 182 วัน → เลื่อนไป 182 วัน** ทำซ้ำจนหมดข้อมูล
- เริ่มหลัง warmup สูงสุด (k=90 + vol 40) เพื่อให้ทุกชุดมีข้อมูลเท่ากัน
- **เกณฑ์คัดเลือกบน train = return / maxDD** ประกาศไว้ล่วงหน้า ตัวเดียว ไม่เปลี่ยน
- ผล test ของแต่ละบล็อกถูกต่อกันแบบทบต้น = เส้นทาง OOS จริงเส้นเดียว

## 3. แขนที่เทียบ (ประกาศครบ)

| id | กฎเลือกพารามิเตอร์ในแต่ละบล็อก |
|---|---|
| **W-OPT** | ชุดที่ดีที่สุดบน train (return/maxDD) |
| **W-FIX** | **ค่าคงที่ k=30 / vol 20 / rebal 7 — control "ไม่ optimize"** |
| **W-MED** | ชุดที่อยู่ **อันดับกลาง** ของ train — วัดว่า "ชุดยอดสุด" พิเศษจริงไหม |
| **W-RND** | สุ่มชุดใหม่ทุกบล็อก · **20 seeds** — **placebo ตามบทเรียน E48** |

## 4. เกณฑ์ตัดสิน

| id | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| **P1** | **harness**: W-FIX เต็มช่วง (ไม่มี funding, 0.15%) ต้องได้ตรง E52: CAGR +71.5% / maxDD 50.9% | ต่าง ≤ 0.5 จุด · **ไม่ผ่าน = หยุด** |
| **P2** | **W-OPT ชนะ W-FIX** บนเส้นทาง OOS ที่ต่อกัน (return/maxDD) | > |
| **P3** | **W-OPT ชนะเปอร์เซ็นไทล์ที่ 90 ของ W-RND** — **ด่านชี้ขาด** | > p90 |
| **P4** | **W-OPT ชนะ W-MED** — ชุดยอดสุดพิเศษกว่าชุดกลางจริงไหม | > |
| P5 | **ความเสถียรของพารามิเตอร์**: ชุดที่ถูกเลือกเปลี่ยนบ่อยแค่ไหน | **รายงาน** |
| P6 | **ตาราง 54 ชุดเต็มช่วง** — การกระจายตัวของผล | **รายงาน** |
| P7 | **อันดับ train เทียบอันดับ test** (Spearman) ทุกบล็อก | **รายงาน** — บอกตรง ๆ ว่าอดีตทำนายอนาคตได้แค่ไหน |

**"การ optimize ช่วยจริง" = P2 และ P3 ผ่าน** · **P3 ตกอย่างเดียวก็พอที่จะปฏิเสธ**

## 5. ตารางการตัดสินใจ (เขียนก่อนเห็นผล)

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| P2+P3+P4 ผ่าน | การเลือกพารามิเตอร์เพิ่มค่าจริง | บันทึกค่าที่ walk-forward เลือก · **ยังไม่ promote** · ขั้นต่อไปคือทดสอบ execution |
| **P3 ตก** | **สุ่มพารามิเตอร์ก็ได้พอกัน** | **คำแนะนำ: ตั้งค่าไว้เฉย ๆ (k=30) จบ** — ยืนยัน E46/E48 อีกครั้ง |
| P2 ตก | การ optimize แย่กว่าไม่ทำอะไร | **คำแนะนำเดียวกัน และแรงกว่า** |
| P2 ผ่าน P4 ตก | ชุดไหนก็ได้ที่พอใช้ได้ | ⚖️ ไม่ใช่ความสามารถในการเลือก |
| P7 แสดง Spearman ≈ 0 | อันดับบนอดีตไม่บอกอะไรเกี่ยวกับอนาคต | **ข้อค้นพบหลัก — รายงานเด่น** |

| P1 ตก | harness เพี้ยน | **หยุด สอบสวนก่อน** |

## 6. สิ่งที่จะไม่ทำ

- **ไม่รายงาน "ชุดที่ดีที่สุดบนข้อมูลทั้งหมด" เป็นคำแนะนำ** — นั่นคือ in-sample
  ล้วน ๆ · จะรายงานในตาราง P6 พร้อมป้ายกำกับว่ามันคืออะไร
- ไม่ขยายตารางพารามิเตอร์หลังเห็นผล · ไม่เปลี่ยนเกณฑ์คัดเลือก · ไม่เปลี่ยนความยาว train/test
- ไม่เพิ่ม seed ถ้าผล placebo ไม่ถูกใจ
- ไม่ใช้ leverage · ไม่แตะ logic ของ M1-LS
- ไม่ promote · ไม่มีคำสั่งจริง · ไม่มีคำแนะนำการลงทุนรายบุคคล
