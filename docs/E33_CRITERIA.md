# E33 — เกณฑ์ตัดสิน (ประกาศก่อนรัน)

> เขียนและบันทึก **ก่อน** เขียนโค้ดของ setup และก่อนเห็นผลใด ๆ
> C1–C7 (ValidationGate) และ G1–G8 (E32) **ไม่ถูกแตะ** — E33 มีเกณฑ์ H1–H10 ของตัวเอง
> ที่ **เข้มกว่า E32** เพราะเพิ่มสองข้อที่ E32 ไม่มีและเป็นข้อที่ทำให้ผู้ชนะของ E32 ตาย

## 1. ทำไมต้องมี E33

`docs/E32_DEPTH_FINDINGS.md` วัดได้ 4 อย่างที่บังคับรูปทรงของ setup นี้:

| หลักฐาน | ข้อบังคับที่ตามมา |
|---|---|
| หางซ้ายอ้วนอยู่**ใต้** SMA-200 (BTC วันแย่สุด −14.4% เหนือเส้น vs −39.5% ใต้เส้น) และ ETH/SOL ใต้เส้นให้ผลตอบแทน**ติดลบ** ขณะ BTC ใต้เส้นยัง **+18.6%/ปี** | ต้องมี**ตัวคัดสินทรัพย์** ไม่ใช่ยิงตัวกรองเดียวกันใส่ทุกเหรียญ |
| leverage ทำให้ CAGR/MAR แย่ลง **monotonic** ทุกกลไก ทุกพอร์ต · funding กิน 27.7%/ปี ที่ 2x · vol drag `(L²−L)/2·σ²` | **gross ≤ 1.0 ตายตัว ห้าม leverage** |
| การเลือกตัวกรองที่ backtest สวยสุด = สุ่ม (E30 §C7 = 20%) | **ห้ามเลือก** ต้องโหวต |
| top-1 episode = 44–56% ของ log growth ทุก candidate | ต้องมี**เกณฑ์การกระจุกตัว** และต้องกระจายข้ามสินทรัพย์เพื่อเพิ่มจำนวนไม้อิสระ |
| Donchian edge หายไปครึ่งหลัง (+19.7% → −12.2%) | ต้องมี**เกณฑ์ decay** |

## 2. Setup ที่จะทดสอบ — ล็อกทุกพารามิเตอร์ ณ บรรทัดนี้

**ชื่อ**: Screened Trend-Vote Basket (STVB)

| องค์ประกอบ | กติกา | ที่มา |
|---|---|---|
| จักรวาล | เหรียญที่มีประวัติ ≥ 400 แท่ง ณ วันตัดสิน | ต้องมีข้อมูลพอคำนวณ SMA-200 + screen |
| **ตัวกรอง (โหวต)** | 1) close > SMA-200 · 2) Donchian-55 breakout state · 3) SMA-50 > SMA-200 | ตำรา ทั้งสามตัวใช้ใน E30/E32 แล้ว ไม่มีตัวใหม่ |
| conviction ต่อเหรียญ | `votes / 3` ∈ {0, ⅓, ⅔, 1} | ไม่มีน้ำหนักปรับ |
| **ตัวคัดสินทรัพย์ (screen)** | รับเฉพาะเหรียญที่ **conditional gap > 0** — คือ mean ผลตอบแทนวันถัดไปตอน "เหนือ SMA-200" ลบด้วยตอน "ใต้" คำนวณจาก **730 แท่งย้อนหลังที่ปิดแล้วเท่านั้น** | กลไกจาก E32-depth §1 · causal ล้วน |
| น้ำหนัก | `w_j ∝ conviction_j / vol_j` (vol = realised 20 วัน annualised) | risk parity ไม่มี optimiser |
| ขนาดพอร์ต | สเกลให้ `Σ w_j·vol_j = 40%` ต่อปี แล้ว **cap gross ที่ 1.00** | vol target 40% เป็นค่าเดิมจาก E32 · cap 1.0 มาจากหลักฐาน leverage |
| รีบาลานซ์ | ทุก 5 แท่ง | เท่ากับ E31 `CrossSectionalMomentum` |
| เมื่อไม่มีเหรียญใดผ่าน | **ถือเงินสด 100%** | ตะกร้าว่างได้โดยการออกแบบ |
| ต้นทุน | spot 0.15%/ขา · ไม่มี funding (gross ≤ 1 ถือ spot ได้) | เท่า E31/E32 |
| การลงมือ | สัญญาณจากแท่ง `i` ลงมือที่ `close[i]` และ **ต้องผ่านการทดสอบ lag** ใน H9 | E32-depth §6 |

**ไม่มีพารามิเตอร์ใดถูกจูนใน E33** ทุกตัวเลขข้างบนมาจากตำราหรือจากค่าที่ประกาศไว้แล้ว
ในเอกสารก่อนหน้า · ห้ามแก้หลังเห็นผล

## 3. ข้อมูล — สิ่งที่ถูกเผาไปแล้วและสิ่งที่ยังสะอาด

| ชุด | สถานะ | ใช้ทำอะไรได้ |
|---|---|---|
| BTC 1d 2017–2026 | **เผาแล้ว** (E30, E31, E32, meta, depth) | รายงานเป็น in-sample เท่านั้น ไม่นับเป็นหลักฐาน |
| ETH, SOL 1d | **เผาแล้ว** (E32 §G6, depth §7) | รายงานได้ ไม่นับเป็นหลักฐาน |
| **30 เหรียญที่เหลือใน universe** | **สะอาดสำหรับกลไกนี้** — E31 ใช้แค่ cross-sectional momentum (คนละกลไก) และ E32/depth ไม่เคยรันตัวกรองรายเหรียญบนมันเลย | **นี่คือหลักฐานหลักของ E33** |

**เกณฑ์หลักตัดสินบน 30 เหรียญที่เหลือเท่านั้น** ผล BTC/ETH/SOL เป็นข้อมูลประกอบ

## 4. Benchmark

1. **equal-weight buy & hold ของจักรวาลเดียวกัน** (ตัวหลัก) — วัดว่ากลไกเพิ่มอะไร
   เหนือการถือทุกอย่างเท่ากัน
2. **BTC buy & hold** (ตัวรอง) — มาตรวัดที่ผู้ใช้จริงเทียบ
3. **buy & hold ที่ลดขนาดด้วยเงินสดจน worst DD เท่ากับ STVB** — กัน "ดีเพราะเสี่ยงน้อย"

## 5. เกณฑ์ H1–H10 (ทุกข้อต้องผ่าน)

| # | เกณฑ์ | ทำไม |
|---|---|---|
| **H1** | CAGR > equal-weight buy & hold ของจักรวาลเดียวกัน | ต้องเพิ่มค่าเหนือการถือเฉย ๆ |
| **H2** | MAR > ของ benchmark ทั้งสอง | ชนะต่อหน่วยความเสี่ยง |
| **H3** | CAGR > buy & hold ที่ลดขนาดจน DD เท่ากัน | กัน "ดีเพราะเสี่ยงน้อย" |
| **H4** | liquidation = 0 และ ruin = 0 | gross ≤ 1 ควรทำให้เป็นไปไม่ได้ — ถ้าเกิดคือมีบั๊ก |
| **H5** | ชนะ benchmark ≥ 5/8 หน้าต่างรายปี | กันผลจากปีเดียว |
| **H6 (ใหม่)** | **top-1 episode < 40% ของ log growth ทั้งหมด** และ **CAGR หลังตัดช่วงที่ดีที่สุดออก ยังชนะ benchmark** | E32-depth §8 — ทุก candidate ก่อนหน้าตายที่ข้อนี้ |
| **H7 (ใหม่)** | **mean edge เหนือ benchmark ในครึ่งหลังของข้อมูล ต้องไม่ติดลบ** (rolling 2 ปี) | E32-depth §4 — Donchian ตายที่ข้อนี้ |
| **H8** | **timing luck**: ช่วงกว้างของ CAGR จาก 12 วันเริ่ม ต้อง < 15 pct pts | E32-depth §3 |
| **H9** | **execution lag 1 วัน ต้องทำให้ CAGR ลดลง < 3 pct pts** | E32-depth §6 — ระบบที่ต้องได้ราคาปิดเป๊ะ ใช้จริงไม่ได้ |
| **H10** | **Deflated Sharpe ≥ 0.95** โดยนับ N = จำนวน variant ทั้งหมดที่ดูในตระกูล E32+E33 | E32-depth §9 |

## 6. ตารางการตัดสินใจ (ประกาศล่วงหน้า)

| ผล | คำตัดสิน |
|---|---|
| ผ่าน H1–H10 ครบ บน 30 เหรียญที่สะอาด | ✅ **candidate ที่แข็งที่สุดที่เคยมีในคลังนี้** → เข้าเส้นทาง paper/testnet ตาม `docs/FIRST_REAL_TRACK_RECORD.md` · **ยังไม่ใช่การเทรดจริง** |
| ตก H6 หรือ H7 | ❌ FAIL — เป็นผลของไม้เดียวหรือ edge ที่ตายแล้ว บันทึกและหยุด |
| ตก H8 หรือ H9 | ❌ FAIL — ผลเป็นอุบัติเหตุของวันเริ่มหรือของสมมติฐานการ fill |
| ตก H10 | ⚖️ บันทึกว่า "แยกจากโชคไม่ได้ที่ขนาดตัวอย่างนี้" ไม่ promote |
| ตกข้ออื่น | ❌ FAIL บันทึกผลลบ |

**ห้ามหลังเห็นผล**: เปลี่ยน vol target, เปลี่ยนหน้าต่าง screen, เพิ่ม/ลดตัวกรอง,
เปลี่ยนจักรวาล, เปลี่ยน rebalance, หรือเพิ่ม candidate ใหม่ — E23–E25 คือบทเรียนนั้น

## 7. อคติที่ทราบล่วงหน้า

1. **Survivorship bias ยังอยู่** — จักรวาลมาจากรายชื่อที่ Binance ลิสต์วันนี้
   (มี WAVES/FTT/LUNC ที่พังจริงปนอยู่ แต่ไม่ครบ) → ผลตะกร้า**ดีเกินจริงเป็นระบบ**
   นี่คืออคติที่ใหญ่ที่สุดของ E33 และ**ไม่มีทางแก้ด้วยข้อมูลชุดนี้**
2. **ช่วงเวลาเดียว** 2017–2026 มี bull cycle ใหญ่สองรอบ
3. ไม่มี slippage ตามขนาด — สมมติฐานทุนเล็ก
4. เหรียญเล็กบางตัวมีสภาพคล่องต่ำจริง ต้นทุน 0.15%/ขาอาจต่ำไปสำหรับมัน
5. **ตัว screen เองมาจากการดูข้อมูล BTC/ETH/SOL** ที่เผาแล้ว — กลไกจึงมี hindsight
   ติดมาหนึ่งชั้น แม้การคำนวณจะ causal ล้วน · นี่คือเหตุผลที่ 30 เหรียญต้องเป็นตัวตัดสิน

## 8. ข้อจำกัดเชิงนโยบายที่ไม่เปลี่ยน

- **ไม่มีการเทรดจริง** ไม่ว่าผลจะเป็นอย่างไร (`CLAUDE.md` § Never)
- ผ่าน E33 ≠ พร้อมใช้เงินจริง — เส้นทางบังคับคือ paper/testnet + track record ที่ปิดผนึก
- setup นี้เป็น **ข้อกำหนดการวิจัย** ไม่ใช่คำแนะนำการลงทุน
- ผลลบบันทึกเท่าเทียมผลบวกใน `docs/VALIDATION_LOG.md`
