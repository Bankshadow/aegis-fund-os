# E51 — ขยายจักรวาลเหรียญ: edge โผล่บนเหรียญที่ไม่เคยใช้ออกแบบไหม (ประกาศก่อนรัน)

> **สถานะ: DECLARED — ยังไม่รัน** (2026-08-14)
> เขียนเสร็จ **ก่อน** แตะโค้ดรันเนอร์ · ห้ามแก้หลังเห็นผล
> จองเลขใน `docs/EXPERIMENT_REGISTRY.md` แล้ว
> **เดินหน้าได้เพราะ E50 §3 แถว "Y3 ตก แต่ Y2 ผ่าน"** — ต้องรายงานใต้เพดานต้นทุน

## 0. คำถาม และทำไมข้อนี้แข็งกว่าการเพิ่มหน้าต่างเวลา

S003 ยืนบน **2 เหรียญ** (SOL, LINK) ซึ่งเป็นชุดที่คนออกแบบใช้สร้างมัน
การเพิ่มหน้าต่างเวลา (E45) ยังใช้เหรียญเดิม การจูน (E46) และ overlay (E47/E48)
ล้มหมด

> **คำถามของ E51: ถ้า edge เป็นของจริง มันต้องโผล่บนเหรียญที่ไม่เคยถูกใช้ออกแบบ**

นี่คือ **cross-sectional out-of-sample** — แข็งกว่าการเพิ่มเวลา เพราะไม่ได้ใช้
ข้อมูลชุดเดิมซ้ำ · และถ้าโผล่จริง จะได้ **diversification** ซึ่งเป็นวิธีลด DD
วิธีเดียวที่ยังไม่ถูกตัดออก (E47/E48 ตัด overlay ไปแล้ว)

## 1. จักรวาล และการเปิดเผยอคติ

**ใช้ `data/universe/spot_1d.json` ทั้งไฟล์ — 33 เหรียญ Binance daily
ไม่คัดเลือกอะไรเพิ่มเอง** (การคัดเองคือช่องทางเข้าของ survivorship)

**ชุดออกแบบ** = `SOL`, `LINK` → **แยกออกจากการตัดสิน**
**ชุดทดสอบ** = **31 เหรียญที่เหลือ** — ไม่เคยถูกใช้ออกแบบ S003

**อคติที่ต้องเปิดเผยและจะเปิดเผยทุกครั้ง**: ไฟล์นี้ถูกประกอบขึ้นในปี 2026
สำหรับการทดลองก่อนหน้า จึงสะท้อน**ความรู้ปี 2026 ว่าเหรียญไหนสำคัญ** = อคติขาขึ้น
· สิ่งที่หักล้างบางส่วน: ไฟล์มีเหรียญที่พังหรือถูกถอด (`WAVES` ข้อมูลจบ 2024-06,
`LUNC`, `FTT`, `ONE`, `SUSHI`) ซึ่งจักรวาลที่คัดด้วย hindsight ล้วนจะไม่มี
· **ไม่อ้างว่าไฟล์นี้เป็น point-in-time** เพราะมันไม่ใช่

เหรียญเข้าทดสอบเมื่อมีบาร์พอสำหรับ warmup ของเอนจิน (201 บาร์) เท่านั้น

## 2. การตั้งค่า (ล็อกก่อนรัน)

**ไม่แตะ entry/exit/stop/target/พารามิเตอร์ใด ๆ** — เอนจินเดียวกับ E44 บิตต่อบิต

**กรณีฐานของ E51 = `sl_first` @ `0.15%`/ข้าง** (กรณีร้ายที่ E50 วัดไว้)
รายงานคู่กับ `tp_first` @ `0.05%` (สเปกเดิม) เสมอ = **2 ชุด × 33 เหรียญ**

**ระดับความเสี่ยง**: 0.25%, 0.5%, 1.0% ต่อไม้ (ต่ำกว่า 2 เหรียญเพราะไม้ซ้อนกันมากขึ้น)
เปิดพร้อมกันได้ **1 ไม้ต่อเหรียญ ไม่จำกัดจำนวนเหรียญ** — รายงานจำนวนไม้ที่ซ้อนกัน
สูงสุดและเฉลี่ย เพื่อให้เห็น exposure จริง

## 3. เกณฑ์ตัดสิน

| id | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| **Z1** | **harness**: เอนจินไม่เปลี่ยน — SOL+LINK (ข้อมูล Yahoo เดิม) ยังให้ portR +72.81 | ต่าง ≤ 0.1 R · **ไม่ผ่าน = หยุด** |
| **Z2** | **การทดสอบหลัก**: portR รวมของ **31 เหรียญนอกชุดออกแบบ** เป็นบวก**ทั้งสองชุด** (sl_first@0.15% และ tp_first@0.05%) | > 0 ทั้งคู่ |
| **Z3** | **สัดส่วนเหรียญที่กำไร** ในชุดทดสอบ ที่กรณีฐาน | **≥ 60%** (≥19/31) |
| **Z4** | **ประโยชน์จากการกระจาย**: พอร์ต 33 เหรียญ ที่ระดับความเสี่ยงที่ให้ CAGR เท่ากับ 2 เหรียญ@1% ต้องได้ **maxDD ต่ำกว่า** | ต่ำกว่า |
| Z5 | **ตารางรายเหรียญครบ 33 ตัว** ทั้งสองชุด | **รายงานเสมอ** |
| Z6 | **แยกผลตามยุคที่ listed** (ก่อน/หลัง 2021) และ**ระบุเหรียญที่ตาย** | **รายงาน** |

**"edge ทั่วไปจริง" = Z1, Z2, Z3 ผ่านครบ**

## 4. ตารางการตัดสินใจ (เขียนก่อนเห็นผล)

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| Z2+Z3 ผ่าน และ Z4 ผ่าน | edge เป็นคุณสมบัติทั่วไปของตลาด ไม่ใช่ของ 2 เหรียญ · และการกระจายช่วยจริง | **ข้อค้นพบที่แข็งที่สุดของสายนี้** · เสนอจักรวาลกว้างเป็น config หลักของ S003 · **ยังห้ามเทรดจริง** |
| Z2 ผ่าน Z3 ตก | กำไรกระจุกในไม่กี่เหรียญ | ⚖️ ระบุว่าเหรียญไหน · ไม่ขยายจักรวาล |
| **Z2 ตก** | **edge ไม่มีอยู่นอก SOL/LINK** | **S003 คือผลของ 2 เหรียญ ไม่ใช่กลยุทธ์** · หยุดสายนี้ · บันทึกเป็นผลลบที่สำคัญที่สุด |
| Z4 ตก แต่ Z2+Z3 ผ่าน | edge ทั่วไป แต่เหรียญคริปโตสัมพันธ์กันเกินกว่าจะกระจายได้ | รายงานว่า diversification ไม่ช่วย — **ปิดทางลด DD ทางสุดท้าย** |
| ผลต่างกันมากระหว่าง 2 ชุด intrabar | ผลไวต่อโมเดลการเติมคำสั่ง | รายงานเป็นข้อจำกัดหลัก |
| Z1 ตก | เอนจินถูกแก้โดยไม่ตั้งใจ | **หยุด สอบสวนก่อน** |

## 5. สิ่งที่จะไม่ทำ

- **ไม่คัดเหรียญเอง** ไม่ว่าก่อนหรือหลังเห็นผล · ไม่ตัดเหรียญที่ขาดทุนทิ้ง
- ไม่จูนพารามิเตอร์ต่อเหรียญ · ไม่ตั้ง max concurrent ที่ fit จากผล
- ไม่อ้างว่าจักรวาลนี้เป็น point-in-time · ไม่ซ่อนอคติขาขึ้นของมัน
- ไม่รายงานเฉพาะ intrabar หรือ fee ที่ดูดี — **2 ชุด 33 เหรียญ เสมอ**
- ไม่ promote · ไม่มีคำสั่งจริง · ไม่มีคำแนะนำการลงทุนรายบุคคล
