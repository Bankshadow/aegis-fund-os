# E49 — ตารางความเสี่ยงต่อไม้ของ S003: DD เป็น "การกระจายตัว" ไม่ใช่ตัวเลขเดียว (ประกาศก่อนรัน)

> **สถานะ: DECLARED — ยังไม่รัน** (2026-08-14)
> เขียนเสร็จ **ก่อน** แตะโค้ด · ห้ามแก้หลังเห็นผล
> จองเลขใน `docs/EXPERIMENT_REGISTRY.md` แล้ว

## 0. คำถาม และสิ่งที่ E49 **ไม่ใช่**

ผู้ใช้ขอ "ลดขนาดไม้และ risk เพื่อให้เอา logic ไปใช้ได้"

**E49 เป็นการวัด ไม่ใช่การค้นหา** ไม่มีการเลือก "ค่าที่ดีที่สุด" ไม่มีการจูน
ไม่มี promote · ผลลัพธ์คือ**ตาราง**ที่แปลง "ความทนต่อ DD ของผู้ใช้" → "ระดับ
ความเสี่ยงต่อไม้" ด้วยกฎที่ประกาศไว้ล่วงหน้า การตัดสินใจเป็นของผู้ใช้ ไม่ใช่ของโมเดล

**ปัญหาที่ต้องแก้**: ทุกตัวเลข DD ที่รายงานมาถึงตอนนี้ (72.1%, 62.5%, 50.9%)
มาจาก **เส้นทางเดียว** — ลำดับเทรดที่บังเอิญเกิดขึ้นจริงครั้งเดียวในประวัติศาสตร์
E47 §U4 วัดแล้วว่างบ DD ที่คาลิเบรตบนอดีต **หลุดทุกแขนบนอนาคต** ดังนั้น
"6% ให้ DD 72%" ไม่ใช่คำสัญญา แต่เป็นการจับฉลากใบเดียว

> **คำถามของ E49: ที่แต่ละระดับความเสี่ยง DD กระจายตัวอย่างไร และระดับไหน
> ที่ทำให้ DD ในกรณีเลวร้าย (p90) ยังอยู่ในงบที่รับได้**

## 1. วิธีวัด (ล็อกก่อนรัน)

**ระดับความเสี่ยงที่วัด** (9 ระดับ ประกาศครบ ห้ามเพิ่ม):
`0.5, 1, 2, 3, 4, 5, 6, 8, 10 %` ต่อไม้ · sizing แบบ **flat เท่านั้น**
(E48 พิสูจน์แล้วว่า overlay ไม่ชนะตัวสุ่มที่ duty cycle เท่ากัน)

**Moving-block bootstrap**: สุ่มบล็อกเทรดต่อเนื่อง **บล็อกละ 10 ไม้** แบบใส่คืน
ให้ครบความยาวเดิม × **500 resamples** ต่อระดับ (seed คงที่ 5000+i)
บล็อกยาว 10 เพื่อ**รักษาการแพ้เป็นกระจุก** — ถ้าสุ่มทีละไม้จะทำลาย clustering
และประเมิน DD ต่ำเกินจริง

**ข้อจำกัดที่ต้องเปิดเผยเสมอ**: bootstrap รันเทรดแบบ**เรียงทีละไม้** จึงไม่มี
การถือซ้อนกันเหมือนของจริง · ดังนั้น**ต้องเทียบกับลำดับจริงที่รันแบบเรียงทีละไม้
เหมือนกัน** (`sequential reference`) ไม่ใช่เทียบกับตัวเลข overlap ของจริง
รายงานทั้งสองอย่างเสมอ

**ช่วงเวลา**: รายงาน IS (2017-11-09→2022-08-01), OOS (2022-08-01→2026-08-13)
และเต็มประวัติ · bootstrap ทำบนเต็มประวัติ (ตัวอย่างมากที่สุด)

## 2. กฎแปลงความทนต่อ DD → ระดับความเสี่ยง (ประกาศก่อนเห็นผล)

> สำหรับความทนต่อ DD ∈ {20%, 30%, 40%, 50%} →
> **เลือกระดับความเสี่ยงที่สูงที่สุดซึ่ง `p90 ของ maxDD จาก bootstrap` ≤ ความทนนั้น**

ใช้ p90 ไม่ใช่มัธยฐาน เพราะการวางแผนพอร์ตต้องวางบนกรณีเลว ไม่ใช่กรณีกลาง
ถ้าไม่มีระดับไหนผ่าน → รายงานว่า **"ไม่มีระดับที่ปลอดภัยพอ"** ตรง ๆ

## 3. สิ่งที่ต้องรายงาน

| id | รายการ | ผ่าน/รายงานเมื่อ |
|---|---|---|
| **X1** | **harness**: flat 6% เต็มประวัติ (แบบ overlap จริง) ต้องได้ DD 72.1% / CAGR +37.2% | ต่าง ≤ 0.5 จุด **ไม่ผ่าน = หยุด** |
| X2 | **ตารางเต็ม 9 ระดับ**: CAGR/DD บน IS, OOS, เต็มประวัติ | รายงานทุกระดับเสมอ |
| X3 | **การกระจายตัวของ DD**: มัธยฐาน / p90 / p95 จาก bootstrap ทุกระดับ | รายงานทุกระดับ |
| X4 | **DD จริงอยู่ตรงไหนของการกระจายตัว** (เปอร์เซ็นไทล์ของเส้นทางจริงเทียบ bootstrap) | รายงาน — ถ้าจริงต่ำกว่ามัธยฐานมาก แปลว่า**ประวัติศาสตร์ใจดีกับเรา** |
| X5 | **อัตราขยายของ DD จาก IS → OOS** ทุกระดับ | รายงาน |
| X6 | **ความเสี่ยงล้างพอร์ต**: สัดส่วน bootstrap path ที่ DD > 80% ทุกระดับ | รายงาน |

## 4. ตารางการตัดสินใจ

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| มีระดับที่ p90 DD ≤ ความทน | ระดับนั้นคือคำตอบสำหรับความทนนั้น | รายงานตาราง · **ผู้ใช้เลือกเอง** |
| ไม่มีระดับไหนที่ p90 DD ≤ 20% | กลยุทธ์นี้ไม่เหมาะกับคนที่ทน DD 20% | **บอกตรง ๆ** ไม่ปัดเศษให้ดูดี |
| DD จริง < มัธยฐาน bootstrap มาก | ตัวเลขที่รายงานมาทั้งหมด**มองโลกในแง่ดีเกินจริง** | **แจ้งเป็นคำเตือนหลัก** |
| X6 > 0 ที่ระดับไหน | ระดับนั้นมีเส้นทางที่พอร์ตแทบหมดตัว | ระบุชัด |
| X1 ตก | harness เพี้ยน | **หยุด สอบสวนก่อน** |

## 5. สิ่งที่จะไม่ทำ

- **ไม่จูนอะไรทั้งสิ้น** — entry/exit/stop/target/overlay คงเดิมทุกตัว
- ไม่เลือก "ระดับที่ดีที่สุด" ให้ผู้ใช้ · ไม่ให้คำแนะนำการลงทุนรายบุคคล
- ไม่ใช้ overlay (E48 ปฏิเสธไปแล้ว) · ไม่เพิ่มระดับความเสี่ยงหลังเห็นผล
- ไม่รายงานเฉพาะระดับที่ดูดี — **9 ระดับ ทุกช่วง เสมอ**
- ไม่อ้างว่า bootstrap = อนาคต — มันคือการสุ่มลำดับจากอดีตเท่านั้น
  **ไม่ครอบคลุมระบอบตลาดที่ไม่เคยเกิด**
- ไม่มีคำสั่งจริง ไม่มี promote
