# E46 — จูน S003 ทีละโมดูล และวัดว่า "การจูน" เพิ่มอะไรจริงไหม (ประกาศก่อนรัน)

> **สถานะ: DECLARED — ยังไม่รัน** (2026-08-12)
> เขียนเสร็จ **ก่อน** แตะโค้ดแม้แต่บรรทัดเดียว ห้ามแก้หลังเห็นผล
> จองเลขใน `docs/EXPERIMENT_REGISTRY.md` แล้ว

## 0. คำถาม และกับดักที่ต้องกันก่อน

ผู้ใช้ขอ "ปรับจูน S003" · สเปกต้นทาง §7 กำหนดวิธีไว้เอง:
**เปลี่ยนทีละโมดูล (entry XOR stop XOR BE XOR filters XOR sizing)** และ §6:
**promote ได้ต่อเมื่อชนะทั้ง portR และ minFold**

**กับดักหลัก**: การกวาดพารามิเตอร์แล้วรายงานตัวที่ดีที่สุด คือรูปแบบ E23–E25
และ ledger นี้วัดไว้แล้วว่า **การเลือกผู้ชนะ in-sample ได้ผล OOS เท่าการสุ่ม**
(Overfitting Lab 16.7% = โอกาสสุ่มพอดี · E30 C7 ทำซ้ำได้ที่ 20% vs 20%)

> **E46 จึงไม่ถามว่า "variant ไหนดีที่สุด" แต่ถามว่า
> "การเลือก variant จากอดีต ให้ผลดีกว่า S003 เดิมในอนาคตหรือไม่"**

ถ้าคำตอบคือไม่ **นั่นคือผลลัพธ์ที่มีค่า** และแปลว่าอย่าจูน

## 1. Baseline ที่ใช้ — ของ E45 ไม่ใช่ของสเปก

E45 แสดงว่า baseline +49.06 R **ถูกช่วยโดยหน้าต่างข้อมูล**: warm-up 201 แท่ง

**E46 จึงเทียบกับ S003 บนประวัติเต็ม 8.8 ปี ซึ่งเป็นบาร์ที่สูงกว่าและถูกต้องกว่า**

| Baseline (E45, ประวัติเต็ม) | ค่า |
|---|---|
| portR (339 เทรด) | **+72.81** |
| fold บวก | 14/17 (82%) |
| fold แย่สุด | −12.51 |
| SOL / LINK | +34.10 / +38.71 |

## 2. การแบ่ง IS / OOS (ล็อกก่อนรัน)

| ช่วง | วันที่เข้าไม้ | ใช้ทำอะไร |
|---|---|---|
| **IS** | 2017-11-09 → 2022-08-01 | **เลือก variant เท่านั้น** |
| **OOS** | 2022-08-01 → 2026-08-12 | **วัดผลเท่านั้น ห้ามใช้เลือก** |

**เหตุผลที่ต้องเทียบ Δ(variant − base) ไม่ใช่ระดับสัมบูรณ์**: ช่วง OOS ทับกับ
หน้าต่างที่คนออกแบบ S003 ค้นหามัน ดังนั้นผลดิบของทุกแขนได้เปรียบเท่ากันหมด
**การหักลบกับ base จึงตัดข้อได้เปรียบนั้นออก** — นี่คือเหตุผลว่าทำไม primary test
เป็นส่วนต่าง ไม่ใช่ค่าสัมบูรณ์

## 3. Variant (ประกาศครบ ห้ามเพิ่มหลังเห็นผล) — เปลี่ยนทีละโมดูลตามสเปก §7

**ทุกแขนเปลี่ยนโมดูลเดียว ที่เหลือเหมือน S003 ทุกตัวอักษร**

| โมดูล | base | ทางเลือกที่ทดสอบ |
|---|---|---|
| A. `SL_BUFFER` (stop) | 0.25 | **0.10**, **0.50** |
| B. `max_risk_atr` (คัดไม้กว้าง) | 3.0 | **2.0**, **4.0** |
| C. BE rule | after_tp2 | **none**, **after_tp1** |
| D. เป้าสุดท้าย (TP3) | 3R | **2R**, **4R** |
| E. `min_stop_atr` (พื้น stop) | 0.5 | **0.25**, **1.0** |

= **10 variant + base = 11 แขน** · **run count = 11 × 2 ช่วง = 22**
ค่าทั้งหมดเป็นค่ารอบ ๆ base แบบสมมาตร (ต่ำกว่า/สูงกว่า อย่างละหนึ่ง)
**ไม่ใช่การกวาดละเอียด** และไม่มีการเลือกค่าหลังเห็นผล

## 4. เกณฑ์ตัดสิน

**เลือก 1 variant จาก IS ด้วย portR สูงสุด** (กฎเดียว ประกาศไว้ก่อน)

| id | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| **T1** | **variant ที่เลือกจาก IS ชนะ base ด้วย OOS portR** | **> base** |
| **T2** | และชนะด้วย **OOS minFold** (กฎ "ทั้งสอง" ของสเปก §6) | **> base** |
| T3 | **มูลค่าของการเลือก**: variant ที่เลือก ชนะ **ค่ามัธยฐาน** ของ variant ทั้ง 10 ใน OOS | ชนะ |
| T4 | สัดส่วน variant ที่ชนะ base ใน OOS | **รายงาน** — ถ้าราว 50% แปลว่าเป็นการโยนเหรียญ |
| T5 | ตรวจ harness: base บนประวัติเต็มต้องได้ **+72.81** | ต่าง ≤ 0.1 R |

**"จูนแล้วดีขึ้น" = T1 และ T2 ผ่าน** · ผ่าน T1 อย่างเดียว = ⚖️ ไม่ใช่ HIT ตามสเปก
**ไม่ว่าผลใด จะไม่ promote ไปเทรดจริง**

## 5. ตารางการตัดสินใจ (เขียนก่อนเห็นผล)

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| T1+T2 ผ่าน และ T3 ผ่าน | การจูนเพิ่มค่าจริง และการเลือกมีสาระ | บันทึกเป็น challenger · **ยังไม่ promote** · ต้องมี held-out ใหม่ |
| T1+T2 ผ่าน แต่ T3 ตก | ได้ variant ที่ดีกว่าโดยบังเอิญ ไม่ใช่เพราะการเลือก | ⚖️ **การจูนไม่ใช่สาเหตุ** |
| **T1 หรือ T2 ตก** | **การเลือกจากอดีตไม่ช่วยในอนาคต** | **ยืนยันบทเรียน E23–E25/C7 อีกครั้ง → หยุดจูน S003** |
| T4 ≈ 50% | variant ชนะ/แพ้ base พอ ๆ กัน | **สัญญาณชัดว่าเป็น noise** |
| T5 ตก | harness เพี้ยน | **หยุด สอบสวนก่อนอ่านผลใด ๆ** |

## 6. สิ่งที่จะไม่ทำ

- **ไม่เปลี่ยนสองโมดูลพร้อมกัน** (สเปก §7)
- ไม่เพิ่ม variant หลังเห็นผล ไม่ขยับ IS/OOS boundary
- ไม่รายงานเฉพาะ variant ที่ดีที่สุด — **รายงานทั้ง 11 แขน ทั้งสองช่วง เสมอ**
- ไม่แตะ known non-beats ในสเปก §6 (4H, iFVG, MA/SMC proxies, TSMOM,
  Donchian+hit-rate, KER, dollar-vol, Reactive Trail)
- ไม่มีคำสั่งจริง ไม่มี promote · สเปกระบุเองว่า research artifact
