# E48 — โจมตี V4 (equity-curve filter) แบบไม่เข้าข้าง และเงื่อนไข promote (ประกาศก่อนรัน)

> **สถานะ: DECLARED — ยังไม่รัน** (2026-08-14)
> เขียนเสร็จ **ก่อน** แตะโค้ดแม้แต่บรรทัดเดียว · ห้ามแก้หลังเห็นผล
> จองเลขใน `docs/EXPERIMENT_REGISTRY.md` แล้ว

## 0. คำสั่งของผู้ใช้ และการแปลเป็นการทดลอง

*"วิเคราะห์ V4 แบบไม่เข้าข้างตัวเอง ถ้าผลลัพธ์ยังดีอยู่โปรโมทเป็น strategic หลัก"*

E47 ให้ V4 ผ่าน U1–U3 แต่หลักฐานคือ **OOS หน้าต่างเดียว** และมีสัญญาณขัดแย้ง
(บน IS การไม่ใช้ overlay เลยชนะทุก overlay) การ promote จากหลักฐานเท่านั้น
คือสิ่งที่ ledger นี้ทำพลาดมาแล้วหลายครั้ง

**E48 ไม่ได้ตั้งใจยืนยัน V4 — ตั้งใจฆ่ามัน** ถ้ามันรอดครบทุกด่าน จึง promote

**นิยาม "promote เป็น strategic หลัก" ในโครงการนี้** = ตั้ง V4 เป็น **default
research config ของ S003** ในเอกสารและโค้ด · **ไม่ใช่การเทรดจริง** กฎ
"ห้าม live-order" และ "ห้ามลดเกณฑ์ ValidationGate" ยังบังคับใช้เต็มรูปแบบ

## 2. กฎ promote (เขียนก่อนเห็นผล ห้ามผ่อน)

> **promote ก็ต่อเมื่อ W1–W6 ผ่าน "ครบทุกด่าน"**
> ตกแม้ด่านเดียว → **V4 คงสถานะ challenger** และรายงานว่าตกด่านไหน

ไม่มี "ผ่านเกือบหมดก็พอ" · ไม่มีการถ่วงน้ำหนัก · ไม่มีการรันซ้ำด้วย seed ใหม่
ถ้าผลไม่ถูกใจ

## 3. ตารางการตัดสินใจ

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| W1–W6 ผ่านครบ | V4 ทนการโจมตีที่ออกแบบมาเพื่อฆ่ามัน | **promote เป็น default research config ของ S003** · อัปเดต `STATE.md` · ยังห้ามเทรดจริง |
| **W1 ตก** | กลไกไม่มีอยู่จริง — สุ่มก็ได้พอกัน | **ปฏิเสธ V4** · คำแนะนำกลับไปที่ "ลดขนาดไม้" |
| W2 ตก | ชนะเพราะ fold เดียว | คงเป็น challenger · ระบุ fold ที่รับผิดชอบ |
| W3 ตก | เปราะต่อพารามิเตอร์ | คงเป็น challenger · รายงานว่าชุดไหนรอด |
| W4 ตก | ข้ออ้าง "กัน loss cluster" เป็นเท็จ | คงเป็น challenger · แก้คำอธิบายกลไกให้ตรงความจริง |
| W5 ตก | หลักฐานมาจากเหรียญเดียว | คงเป็น challenger |
| W6 ตก | ที่จริงคือผลของ leverage ไม่ใช่ overlay | **ปฏิเสธ V4** — เท่ากับ E47 U1 ถูกบิดด้วยขนาดไม้ |
| W7 ตก | harness เพี้ยน | **หยุด สอบสวนก่อน** |

## 4. สิ่งที่จะไม่ทำ

- **ไม่แตะ entry/exit/stop/target** — sizing overlay เท่านั้น
- **ไม่คาลิเบรต `base_risk` ใหม่** ยกเว้นใน W6 ที่ประกาศไว้ว่าเป็น diagnostic
- ไม่เพิ่ม seed หรือด่านหลังเห็นผล · ไม่เลือกรายงานเฉพาะด่านที่ผ่าน
- ไม่เปลี่ยนช่วง IS/OOS · ไม่ขยายข้อมูล
- **ไม่ promote ถ้าตกแม้ด่านเดียว** ต่อให้ตัวเลข OOS ดูสวย
- ไม่มีคำสั่งจริง ไม่มีคำแนะนำการลงทุนรายบุคคล
