## 0. ข้อสังเกตที่ทำให้การทดลองนี้มีความหมาย

`BORA_V2_Development_Spec.md` วางแกนกลางไว้ว่า:

> **Aggression ≠ Control** · Extreme aggressive flow + Low price impact = Absorption

**S003 คือ absorption detector อยู่แล้ว เพียงแต่ใช้ราคาเป็นตัวแทนของ flow**

| BORA | S003 |
|---|---|
| Buy Absorption (§11): buy aggression สุดขั้ว + ราคาขึ้นไม่ได้ → SHORT | Red 2U: เบรกไฮแล้วปิดแดง → SHORT |
| Sell Absorption (§10): sell aggression สุดขั้ว + ราคาลงไม่ได้ → LONG | Green 2D: เบรกโลว์แล้วปิดเขียว → LONG |

แท่งที่เบรกไฮได้แต่ปิดแดง **คือ**นิยามของ "แรงซื้อขยับราคาไม่สำเร็จ" ที่วัดจาก OHLC
เพียงอย่างเดียว ⇒ ทั้งสองสเปกอธิบายกลไกเดียวกัน ต่างกันที่ **BORA วัด flow ตรง ๆ
ส่วน S003 อนุมานจากรูปแท่ง**

> **คำถามของ E59: การวัด flow ตรง ๆ ด้วย taker-buy volume จริง เพิ่มอะไรเหนือ
> ตัวแทนราคาที่ S003 ใช้อยู่แล้วหรือไม่**

นี่คือ **BORA §22 (Control Group)** และ **BORA §25 (Incremental Edge)**
บังคับใช้จริง โดยมีด่านที่สเปก BORA ไม่ได้ตั้งเพิ่มเข้ามา (§3 V3)

## 1. ตลาดและข้อมูล — และข้อจำกัดที่ต้องพูดทุกครั้ง

**BTCUSDT รายวัน 3,276 แท่ง (2017-08-17 → 2026-08-05)** — Binance klines ดิบ
ฟิลด์ครบ `QuoteVolume` และ `TakerBuyQuoteVolume`

ผ่าน BORA §4 Data Quality Gate แล้ว: ไม่มี timestamp ซ้ำ · ไม่มีแท่ง volume = 0 ·
`TakerBuyQuote <= Quote` ทุกแท่ง · **สถานะ `VALID`**

> **ข้อจำกัดที่ทำให้ผลนี้ไม่ generalize เอง**: BTC รายวัน **ไม่ใช่ตลาดที่ BORA
> ตั้งใจ** (5m) และ **ไม่ใช่ตลาดที่ S003 ผ่านการตรวจสอบ** (SOL+LINK รายวัน) ·
> มันเป็นที่เดียวที่วัดทั้งสองอย่างบนแท่งเดียวกันได้ เพราะ SOL/LINK ในรีโปนี้
> มาจากแหล่งที่ **ไม่มีข้อมูล taker-buy** · E51 พิสูจน์แล้วว่า S003 ไม่ generalize
> ข้ามเหรียญ ดังนั้น **ผลบวกที่นี่ไม่ใช่หลักฐานว่า BORA ช่วย S003 บน SOL/LINK**
> และผลลบก็ไม่ใช่หลักฐานว่า BORA ใช้ไม่ได้บน 5m

## 2. นิยามที่ล็อกก่อนรัน

**Base**: S003 ตาม `docs/S003_SPEC.md` ทุกบรรทัด ห้ามแตะ entry/stop/target/fee/warmup

**Order flow** (BORA §5–§9):

```
BuyVol   = TakerBuyQuoteVolume
SellVol  = QuoteVolume - TakerBuyQuoteVolume
Delta    = BuyVol - SellVol
Delta_Z  = (Delta - mean(Delta, 100)) / std(Delta, 100)        # BORA §7 initial window
PriceImpact     = |close - open| / ATR(14)                      # BORA §8
AbsorptionScore = |Delta_Z| / (PriceImpact + 0.10)              # BORA §9, eps = 0.10
```

ทุกค่าใช้ข้อมูลถึงแท่งนั้นเท่านั้น · ตัวกรองประเมินที่ **แท่งสัญญาณ** และตัดสิน
**ก่อน**เข้าไม้ · ตัวกรองไม่แตะ stop/target/การจัดการไม้

**แขนที่ทดสอบ (ประกาศครบ ห้ามเพิ่มหลังเห็นผล)**

| แขน | กฎ |
|---|---|
| **M0** | S003 เปล่า ไม่มีตัวกรอง — baseline |
| **M1** | **BORA-aligned**: flow ต้อง**ยืนยัน** absorption ในทิศของไม้ · SHORT (red 2U) ต้องมี `Delta_Z >= +Zt` · LONG (green 2D) ต้องมี `Delta_Z <= -Zt` |
| **M2** | **ความแรงอย่างเดียว**: `|Delta_Z| >= Zt` ไม่สนทิศ |
| **M3** | **AbsorptionScore** อยู่ใน percentile `q` บนสุดของ 100 แท่งย้อนหลัง |
| **M4** | **Group B ของ BORA §22**: ส่วนเติมเต็มของ M1 — เก็บเฉพาะไม้ที่ flow **ไม่ยืนยัน** |
| **P** | **placebo**: สุ่มเก็บไม้ที่ duty cycle เท่ากับแขนที่เทียบ × **20 seeds** (seed 9000+i) |

**พารามิเตอร์ (ประกาศครบ)**: `Zt ∈ {1.5, 2.0, 2.5}` (BORA §7) · `q ∈ {90, 95}`
**ค่าหลักคือ `Zt = 2.0`** ตามที่ BORA §10/§11 เขียนไว้เอง — ไม่ใช่ค่าที่เลือกจากผล

## 3. เกณฑ์

| id | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| **V1** | **harness**: M0 ต้องได้ไม้เท่ากับเอนจิน S003 รันตรง ๆ บน BTC รายวัน (**221 ไม้**) และวันเข้าไม้ตรงกันทุกไม้ | ตรงทั้งหมด · **ไม่ผ่าน = หยุด** |
| **V2** | **การทดสอบของ BORA เอง (§22)**: ที่ `Zt=2.0` — M1 portR **>** M4 portR | M1 > M4 |
| **V3** | **ด่านที่สเปก BORA ไม่ได้ตั้ง**: M1 ต้องชนะ **p90 ของ placebo** ที่ duty cycle เดียวกัน 20 seeds | M1 > p90 |
| **V4** | **Incremental edge (BORA §25)**: M1 portR **>** M0 portR | M1 > M0 |
| **V5** | **เสถียรภาพพารามิเตอร์ (BORA §23)**: M1 ชนะ M0 กี่ค่าจาก `Zt` ทั้งสาม | ≥ **2 จาก 3** |
| V6 | จำนวนไม้และ duty cycle ของทุกแขน ทุกพารามิเตอร์ | **รายงานครบ** |
| V7 | ผลใต้มุมร้าย (`sl_first` + 0.15%/ข้าง) ของ M0 และ M1 | **รายงาน** |
| V8 | M0 และ M1 เทียบ **ถือ BTC เฉย ๆ** ที่ risk 1% บนหน้าต่างเดียวกัน | **รายงาน** — ไม่ใช่เกณฑ์ผ่าน/ตก (ตัวอย่างเหรียญเดียว) |

**"order flow เพิ่ม edge จริง" = V1 ผ่าน และ V2, V3, V4 ผ่านครบที่ `Zt = 2.0`**

V2 อย่างเดียวไม่พอ เพราะการกรองใด ๆ ที่ทำให้เทรดน้อยลงอาจดูดีขึ้นโดยบังเอิญ —
**V3 คือด่านที่ E48 พิสูจน์แล้วว่าฆ่า overlay ที่ผ่าน V2/V4 มาแล้วได้**
สเปก BORA มี control group (§22) แต่**ไม่มี placebo** ซึ่งเป็นคนละอย่างกัน:
control group ถามว่า "absorption ดีกว่าไม่มี absorption ไหม" · placebo ถามว่า
"ดีกว่าการสุ่มทิ้งไม้จำนวนเท่ากันไหม"

## 4. ตารางการตัดสินใจ (เขียนก่อนเห็นผล)

| ผล | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| V2+V3+V4 ผ่าน | order flow เพิ่ม edge เหนือตัวแทนราคาจริง | คุ้มที่จะทำ BORA เต็มรูปบน 4H/5m · เขียน criteria ใหม่ ไม่ต่อยอดจากอันนี้ |
| V2 ผ่าน V3 ตก | ประโยชน์คือ **"เทรดน้อยลง" ไม่ใช่ "อ่าน flow ได้"** | ซ้ำรอย E48 · ไม่คุ้มลงทุนต่อใน absorption filter |
| V4 ตก | ตัวกรองตัดไม้ดีทิ้งมากกว่าไม้แย่ | รายงานว่าตัวแทนราคาของ S003 **จับ absorption ได้ครบแล้ว** |
| **V2 ตก** | นิยาม absorption ของ BORA ไม่มี edge บนข้อมูลและสัญญาณฐานชุดนี้ | ตามคำพูดของสเปก BORA เอง §22 |
| V5 ตก แต่ V2–V4 ผ่าน | `Zt=2.0` เป็นจุดโดด ๆ | สัญญาณ overfit (บทเรียน E53) |
| V1 ตก | harness เพี้ยน | **หยุด สอบสวน** |

## 5. สิ่งที่จะไม่ทำ

- **ไม่จูน** entry/stop/target/fee/warmup ของ S003 · ไม่เพิ่มค่า `Zt`/`q` หลังเห็นผล
- ไม่ใช้ BORA Score (§32) — 8 องค์ประกอบถ่วงน้ำหนักพร้อม threshold คือสิ่งที่
  E53/E54 ฆ่าไปแล้ว ต้องพิสูจน์ทีละชิ้นก่อน ไม่ใช่รวมร่างแล้วจูน
- ไม่ทดสอบ M0–M5 ladder ของ BORA §25 เต็มรูป — E59 ถามคำถามเดียว
- ไม่รายงานเฉพาะแขนที่ดูดี — **ทุกแขน ทุกพารามิเตอร์ เสมอ**
- ไม่อ้างว่าผลบน BTC รายวันบอกอะไรเกี่ยวกับ 5m หรือเกี่ยวกับ SOL/LINK
- ไม่ promote · ไม่มีคำสั่งจริง · ไม่ลดเกณฑ์ ValidationGate
