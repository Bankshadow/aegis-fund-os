## 1. คำถามวิจัย

> Grid บนหุ้น AOT (SET) ที่มีต้นทุนไทยจริง (commission + exchange fee + VAT 7%
> + slippage) **สร้าง alpha เหนือ buy-and-hold ได้อย่างมีนัยสำคัญหรือไม่**
> เมื่อวัดแบบ out-of-sample ที่ไม่มี lookahead ในการเลือกพารามิเตอร์?

**สมมติฐานว่าง (H0)**: ไม่ได้ — alpha ที่เห็นใน in-sample คือผลของการเลือก
พารามิเตอร์ย้อนหลัง และจะหายไปใน OOS

**เหตุผลที่ต้องเทียบ buy-and-hold ไม่ใช่ cash**: AOT เป็นหุ้นที่ราคาขึ้นจาก
~5 THB (2005) เป็น ~64 THB (2026) การ "ชนะ cash" จึงไม่มีความหมาย — grid ที่
ถือ inventory ไว้เฉย ๆ ก็ชนะ cash ได้ **benchmark ที่ถูกต้องคือถือหุ้นเฉย ๆ**

## 3. Protocol (ประกาศก่อนรัน — ห้ามแก้หลังเห็นผล)

### 3.1 Walk-forward แบบ anchored-rolling

- **หน้าต่าง in-sample (IS)**: 504 แท่ง (~2 ปีทำการ)
- **หน้าต่าง out-of-sample (OOS)**: 252 แท่ง (~1 ปีทำการ)
- **ก้าว**: 252 แท่ง (fold ไม่ทับซ้อนกันในฝั่ง OOS)
- ได้ประมาณ **18 fold** จาก 5,273 แท่ง

**กฎห้าม lookahead ที่เข้มที่สุดของงานนี้**: `lowerPrice` / `upperPrice` /
`gridCount` / `gridType` ของแต่ละ fold ต้องคำนวณจาก **แท่ง IS เท่านั้น**
ราคา AOT วิ่งจาก 5 → 64 THB การตั้ง grid range ครอบทั้งช่วงคือการโกงที่
มองไม่เห็น — และเป็นสาเหตุที่ผลจะสวยเกินจริงถ้าไม่ระวัง

### 3.2 "≥3 seeds" บนข้อมูลจริงหมายถึงอะไร

ข้อมูลจริงมีเส้นเดียว จึงไม่มี seed แบบ synthetic กฎ ≥3 seeds ถูกแปลเป็น
**ความหลากหลาย 3 แกน** และต้องผ่านทุกแกน:

1. **Fold** — ≥18 หน้าต่าง OOS ที่ไม่ทับกัน
2. **Config perturbation** — เขย่า `gridCount` ±2 และ range ±10% รอบค่าที่ IS เลือก (≥9 combination ต่อ fold)
3. **Execution mode** — รันซ้ำด้วย `CONSERVATIVE_OHLC` และ `WORST_CASE`
   (`OPTIMISTIC_OHLC` ใช้เพื่อ**วัดขนาดของ optimism bias** เท่านั้น ห้ามใช้อ้างผลผ่าน)

### 3.3 คะแนน

- **Robust score** = `totalReturn − 2 × maxDrawdown` (กฎเดิมของโปรเจกต์, ไม่เจรจา)
- **Alpha** = `totalReturn − buyAndHoldReturn` ในหน้าต่าง OOS เดียวกัน (engine คำนวณให้แล้ว)
- นับเฉพาะ fold ที่ **engaged** (มี fill ≥ 1 คู่ครบ cycle) — fold ที่ไม่เทรดเลย
  ไม่ถือเป็น "ชนะ" แต่ถูกนับใน denominator ของ C4

### 3.4 Multiple-testing

จำนวนการรันทั้งหมด (fold × perturbation × mode) ต้องถูก**นับและบันทึก** และ
เกณฑ์นัยสำคัญต้องปรับด้วย Bonferroni ตามจำนวน config ที่ทดสอบจริง
ห้ามรายงานเฉพาะ config ที่ดีที่สุด — ต้องรายงาน **การกระจายทั้งหมด**

## 4. เกณฑ์ผ่าน (ทุกข้อต้องผ่าน — AND ไม่ใช่ OR)

| # | เกณฑ์ | เหตุผล |
|---|---|---|
| **C1** | **mean robust score บน OOS ทุก fold > 0** | กฎเดิม — เดียวกับที่ Line-B ใช้แล้วไม่ผ่าน |
| **C2** | **mean alpha บน OOS > 0** และ **ชนะ buy-and-hold ใน > 50% ของ fold** | ถ้าแพ้การถือเฉย ๆ grid ไม่มีเหตุผลให้มีอยู่ |
| **C3** | **maxDrawdown เฉลี่ยบน OOS ≤ maxDrawdown ของ buy-and-hold** | grid ขายเป็นชั้น ๆ ควรลด DD ได้ ถ้าไม่ได้แปลว่าได้แต่ความเสี่ยง |
| **C4** | **engaged ≥ 50% ของ fold** | เกณฑ์เดียวกับ E17/E18/E20 ที่เคยตกด้วยข้อนี้ |
| **C5** | **ผ่าน C1–C4 ทั้งใน `CONSERVATIVE_OHLC` และ `WORST_CASE`** | ผลที่พังทันทีเมื่อสมมติฐานการ fill แย่ลง = ไม่ทนทาน |
| | ⚠️ **หมายเหตุหลังรัน**: บน daily bar เกณฑ์นี้อ่อนมาก — `ambiguousBars = 0` ทุก fold และโหมดต่างกันเฉพาะลำดับ fill ภายในแท่ง อีกทั้งโหมดครอบขอบเขตแค่ *คุณภาพของแต่ละ fill* ไม่ใช่ผลระดับพอร์ต (ดู VALIDATION_LOG § E26 "การแก้ execution mode") **การทดลองครั้งหน้าต้องใช้ intraday จึงจะให้ C5 มีน้ำหนัก** | |
| **C6** | **`isReconciled === true` และ `ambiguousBars` ≤ 5% ของแท่ง ในทุก fold** | ถ้าบัญชีไม่ตรง ตัวเลขอื่นไม่มีความหมาย |
| **C7** | **ผิวสัมผัสพารามิเตอร์เป็น "ที่ราบ" ไม่ใช่ "ยอดเข็ม"** — ≥ 60% ของ perturbation รอบค่าที่เลือก ต้องได้ robust > 0 | ยอดเข็ม = overfit ตามบทเรียน E3 |

**เกณฑ์ที่ไม่ใช่เกณฑ์ผ่าน แต่ต้องรายงานเสมอ**: optimism gap
(`OPTIMISTIC` − `CONSERVATIVE`), total fees + VAT ที่จ่ายไปทั้งหมด,
peak capital utilization, ending inventory exposure, forced liquidation

## 6b. E28 — Trailing / re-anchor grid (ประกาศ 2026-07-23, ก่อนรัน)

> **สถานะ: RUN แล้ว — ⚖️ ผ่าน M1–M3 แต่ตก C1/C2/C7** (2026-07-23)
> alpha −10.79 → −9.40, engaged 83% → 100%, แลกกับ DD 15.17% → 16.84%
> รายละเอียดใน `VALIDATION_LOG.md` § E28 · ข้อความเกณฑ์ด้านล่างไม่ถูกแก้หลังรัน

> ต่อจาก E27 ที่พิสูจน์ว่า "กรองว่าเทรดหรือไม่เทรด" ไม่พอโดยหลักการ
> เพราะ limit order ที่ถูกระงับก็ fill ที่ราคาเดิมอยู่ดี

**สมมติฐานระดับกลไก**: ถ้าราคาหลุดขึ้นเหนือ grid (ขายหมดแล้วราคาวิ่งหนี — สาเหตุ
ที่ E26 ระบุ) ให้ **ยกทั้ง grid ขึ้นตามราคา**: ยกเลิก order ที่ค้าง แล้ววาง
ระดับใหม่โดยคง**ความกว้างและรูปทรงเดิม** ให้ราคาปัจจุบันกลับมาอยู่กลาง grid
grid จึงกลับมาเทรดได้แทนที่จะยืนดู

**ตัวแปรเดียวที่เปลี่ยนจาก baseline E26**: `trailing` — fold, ต้นทุน, ทุน,
วิธีเลือก geometry, execution mode เหมือนเดิมทั้งหมด

**พารามิเตอร์ กำหนดตายตัวล่วงหน้า ไม่มีรอบจูน**:
- trigger: `close > upperPrice` (ราคาปิดหลุดเหนือระดับบนสุด)
- การยก: เลื่อนทั้งชุดขึ้นให้ `upper` ใหม่ = close ปัจจุบัน คงอัตราส่วน lower/upper เดิม
- **ยกขึ้นอย่างเดียว (TRAIL_UP)** ไม่ยกลง — การยกลงคือการไล่ราคาขาลง
  ซึ่งเป็นกลไกคนละตัวและ **ไม่ได้ทดสอบในรอบนี้**
- inventory/cash ไม่ถูกแตะตอนยก; ไม่มีการบังคับขาย

**เกณฑ์**: C1–C7 เดิมทั้งหมด (ห้ามลด) **บวก** เกณฑ์เฉพาะกลไก:
- **M1**: mean alpha ต้อง **> −10.79** (ดีกว่า baseline E26) มิฉะนั้นกลไกไม่มีผล
- **M2**: 4 fold ที่ E26/E27 แพ้หนักที่สุด (fold 3, 6, 7, 11) ต้อง **ขยับจริง** —
  ถ้าตัวเลขยังเท่าเดิมแปลว่ากลไกไม่ได้แตะปัญหาอีกครั้ง (บทเรียนตรงจาก E27)
- **M3**: ต้องไม่ทำให้ maxDD แย่ลงกว่า buy-and-hold (C3 ยังต้องผ่าน)

**คำตัดสินที่เป็นไปได้ (เขียนก่อนรู้ผล)**:

| ผล | คำตัดสิน |
|---|---|
| ผ่าน C1–C7 | 🟢 มีหลักฐาน OOS ครั้งแรก — ขั้นถัดไป capacity + promotion gate |
| ตก C1–C7 แต่ผ่าน M1+M2 | ⚖️ กลไกมีทิศทางถูก บันทึกเป็นผลบางส่วน ยังไม่ promote |
| ตก M1 หรือ M2 | ❌ ปิดสาย trailing — และ **ห้ามจูน trigger/ความกว้าง** ตามบทเรียน E23–E25/E27 |
