## 1. คำถามวิจัย

> Grid บนหุ้น AOT (SET) ที่มีต้นทุนไทยจริง (commission + exchange fee + VAT 7%
> + slippage) **สร้าง alpha เหนือ buy-and-hold ได้อย่างมีนัยสำคัญหรือไม่**
> เมื่อวัดแบบ out-of-sample ที่ไม่มี lookahead ในการเลือกพารามิเตอร์?

**สมมติฐานว่าง (H0)**: ไม่ได้ — alpha ที่เห็นใน in-sample คือผลของการเลือก
พารามิเตอร์ย้อนหลัง และจะหายไปใน OOS

**เหตุผลที่ต้องเทียบ buy-and-hold ไม่ใช่ cash**: AOT เป็นหุ้นที่ราคาขึ้นจาก
~5 THB (2005) เป็น ~64 THB (2026) การ "ชนะ cash" จึงไม่มีความหมาย — grid ที่
ถือ inventory ไว้เฉย ๆ ก็ชนะ cash ได้ **benchmark ที่ถูกต้องคือถือหุ้นเฉย ๆ**

## 3. Protocol (ประกาศก่อนรัน — ห้ามแก้หลังเห็นผล)

### 3.1 Walk-forward แบบ anchored-rolling

- **หน้าต่าง in-sample (IS)**: 504 แท่ง (~2 ปีทำการ)
- **หน้าต่าง out-of-sample (OOS)**: 252 แท่ง (~1 ปีทำการ)
- **ก้าว**: 252 แท่ง (fold ไม่ทับซ้อนกันในฝั่ง OOS)
- ได้ประมาณ **18 fold** จาก 5,273 แท่ง

**กฎห้าม lookahead ที่เข้มที่สุดของงานนี้**: `lowerPrice` / `upperPrice` /
`gridCount` / `gridType` ของแต่ละ fold ต้องคำนวณจาก **แท่ง IS เท่านั้น**
ราคา AOT วิ่งจาก 5 → 64 THB การตั้ง grid range ครอบทั้งช่วงคือการโกงที่
มองไม่เห็น — และเป็นสาเหตุที่ผลจะสวยเกินจริงถ้าไม่ระวัง

### 3.2 "≥3 seeds" บนข้อมูลจริงหมายถึงอะไร

ข้อมูลจริงมีเส้นเดียว จึงไม่มี seed แบบ synthetic กฎ ≥3 seeds ถูกแปลเป็น
**ความหลากหลาย 3 แกน** และต้องผ่านทุกแกน:

1. **Fold** — ≥18 หน้าต่าง OOS ที่ไม่ทับกัน
2. **Config perturbation** — เขย่า `gridCount` ±2 และ range ±10% รอบค่าที่ IS เลือก (≥9 combination ต่อ fold)
3. **Execution mode** — รันซ้ำด้วย `CONSERVATIVE_OHLC` และ `WORST_CASE`
   (`OPTIMISTIC_OHLC` ใช้เพื่อ**วัดขนาดของ optimism bias** เท่านั้น ห้ามใช้อ้างผลผ่าน)

### 3.3 คะแนน

- **Robust score** = `totalReturn − 2 × maxDrawdown` (กฎเดิมของโปรเจกต์, ไม่เจรจา)
- **Alpha** = `totalReturn − buyAndHoldReturn` ในหน้าต่าง OOS เดียวกัน (engine คำนวณให้แล้ว)
- นับเฉพาะ fold ที่ **engaged** (มี fill ≥ 1 คู่ครบ cycle) — fold ที่ไม่เทรดเลย
  ไม่ถือเป็น "ชนะ" แต่ถูกนับใน denominator ของ C4

### 3.4 Multiple-testing

จำนวนการรันทั้งหมด (fold × perturbation × mode) ต้องถูก**นับและบันทึก** และ
เกณฑ์นัยสำคัญต้องปรับด้วย Bonferroni ตามจำนวน config ที่ทดสอบจริง
ห้ามรายงานเฉพาะ config ที่ดีที่สุด — ต้องรายงาน **การกระจายทั้งหมด**

## 4. เกณฑ์ผ่าน (ทุกข้อต้องผ่าน — AND ไม่ใช่ OR)

| # | เกณฑ์ | เหตุผล |
|---|---|---|
| **C1** | **mean robust score บน OOS ทุก fold > 0** | กฎเดิม — เดียวกับที่ Line-B ใช้แล้วไม่ผ่าน |
| **C2** | **mean alpha บน OOS > 0** และ **ชนะ buy-and-hold ใน > 50% ของ fold** | ถ้าแพ้การถือเฉย ๆ grid ไม่มีเหตุผลให้มีอยู่ |
| **C3** | **maxDrawdown เฉลี่ยบน OOS ≤ maxDrawdown ของ buy-and-hold** | grid ขายเป็นชั้น ๆ ควรลด DD ได้ ถ้าไม่ได้แปลว่าได้แต่ความเสี่ยง |
| **C4** | **engaged ≥ 50% ของ fold** | เกณฑ์เดียวกับ E17/E18/E20 ที่เคยตกด้วยข้อนี้ |
| **C5** | **ผ่าน C1–C4 ทั้งใน `CONSERVATIVE_OHLC` และ `WORST_CASE`** | ผลที่พังทันทีเมื่อสมมติฐานการ fill แย่ลง = ไม่ทนทาน |
| | ⚠️ **หมายเหตุหลังรัน**: บน daily bar เกณฑ์นี้อ่อนมาก — `ambiguousBars = 0` ทุก fold และโหมดต่างกันเฉพาะลำดับ fill ภายในแท่ง อีกทั้งโหมดครอบขอบเขตแค่ *คุณภาพของแต่ละ fill* ไม่ใช่ผลระดับพอร์ต (ดู VALIDATION_LOG § E26 "การแก้ execution mode") **การทดลองครั้งหน้าต้องใช้ intraday จึงจะให้ C5 มีน้ำหนัก** | |
| **C6** | **`isReconciled === true` และ `ambiguousBars` ≤ 5% ของแท่ง ในทุก fold** | ถ้าบัญชีไม่ตรง ตัวเลขอื่นไม่มีความหมาย |
| **C7** | **ผิวสัมผัสพารามิเตอร์เป็น "ที่ราบ" ไม่ใช่ "ยอดเข็ม"** — ≥ 60% ของ perturbation รอบค่าที่เลือก ต้องได้ robust > 0 | ยอดเข็ม = overfit ตามบทเรียน E3 |

**เกณฑ์ที่ไม่ใช่เกณฑ์ผ่าน แต่ต้องรายงานเสมอ**: optimism gap
(`OPTIMISTIC` − `CONSERVATIVE`), total fees + VAT ที่จ่ายไปทั้งหมด,
peak capital utilization, ending inventory exposure, forced liquidation

## 6b. E28 — Trailing / re-anchor grid (ประกาศ 2026-07-23, ก่อนรัน)

> **สถานะ: RUN แล้ว — ⚖️ ผ่าน M1–M3 แต่ตก C1/C2/C7** (2026-07-23)
> alpha −10.79 → −9.40, engaged 83% → 100%, แลกกับ DD 15.17% → 16.84%
> รายละเอียดใน `VALIDATION_LOG.md` § E28 · ข้อความเกณฑ์ด้านล่างไม่ถูกแก้หลังรัน

> ต่อจาก E27 ที่พิสูจน์ว่า "กรองว่าเทรดหรือไม่เทรด" ไม่พอโดยหลักการ
> เพราะ limit order ที่ถูกระงับก็ fill ที่ราคาเดิมอยู่ดี

**สมมติฐานระดับกลไก**: ถ้าราคาหลุดขึ้นเหนือ grid (ขายหมดแล้วราคาวิ่งหนี — สาเหตุ
ที่ E26 ระบุ) ให้ **ยกทั้ง grid ขึ้นตามราคา**: ยกเลิก order ที่ค้าง แล้ววาง
ระดับใหม่โดยคง**ความกว้างและรูปทรงเดิม** ให้ราคาปัจจุบันกลับมาอยู่กลาง grid
grid จึงกลับมาเทรดได้แทนที่จะยืนดู

**ตัวแปรเดียวที่เปลี่ยนจาก baseline E26**: `trailing` — fold, ต้นทุน, ทุน,
วิธีเลือก geometry, execution mode เหมือนเดิมทั้งหมด

**พารามิเตอร์ กำหนดตายตัวล่วงหน้า ไม่มีรอบจูน**:
- trigger: `close > upperPrice` (ราคาปิดหลุดเหนือระดับบนสุด)
- การยก: เลื่อนทั้งชุดขึ้นให้ `upper` ใหม่ = close ปัจจุบัน คงอัตราส่วน lower/upper เดิม
- **ยกขึ้นอย่างเดียว (TRAIL_UP)** ไม่ยกลง — การยกลงคือการไล่ราคาขาลง
  ซึ่งเป็นกลไกคนละตัวและ **ไม่ได้ทดสอบในรอบนี้**
- inventory/cash ไม่ถูกแตะตอนยก; ไม่มีการบังคับขาย

**เกณฑ์**: C1–C7 เดิมทั้งหมด (ห้ามลด) **บวก** เกณฑ์เฉพาะกลไก:
- **M1**: mean alpha ต้อง **> −10.79** (ดีกว่า baseline E26) มิฉะนั้นกลไกไม่มีผล
- **M2**: 4 fold ที่ E26/E27 แพ้หนักที่สุด (fold 3, 6, 7, 11) ต้อง **ขยับจริง** —
  ถ้าตัวเลขยังเท่าเดิมแปลว่ากลไกไม่ได้แตะปัญหาอีกครั้ง (บทเรียนตรงจาก E27)
- **M3**: ต้องไม่ทำให้ maxDD แย่ลงกว่า buy-and-hold (C3 ยังต้องผ่าน)

**คำตัดสินที่เป็นไปได้ (เขียนก่อนรู้ผล)**:

| ผล | คำตัดสิน |
|---|---|
| ผ่าน C1–C7 | 🟢 มีหลักฐาน OOS ครั้งแรก — ขั้นถัดไป capacity + promotion gate |
| ตก C1–C7 แต่ผ่าน M1+M2 | ⚖️ กลไกมีทิศทางถูก บันทึกเป็นผลบางส่วน ยังไม่ promote |
| ตก M1 หรือ M2 | ❌ ปิดสาย trailing — และ **ห้ามจูน trigger/ความกว้าง** ตามบทเรียน E23–E25/E27 |

## 6c. E29 — Trailing + exposure cap ตอน re-anchor (ประกาศ 2026-07-25, ก่อนรัน)

> **สถานะ: RUN แล้ว — ⚖️ M1–M3 ผ่านบน mean แต่ decomposition ล้ม, gate FAIL** (2026-07-25)
> robust −19.91 → −12.17, DD 16.84% → 13.52% แต่ผลดีเป็น selection artifact +
> fold ที่หยุดเทรด (engaged 100% → 78%) ไม่ใช่กลไก · ห้ามจูน cap/trigger ต่อ
> รายละเอียดใน `VALIDATION_LOG.md` § E29 · ข้อความเกณฑ์ด้านล่างไม่ถูกแก้หลังรัน

> ต่อจาก E28 ที่พิสูจน์ว่า trailing ทำให้ grid กลับมาเทรดจริง (M1–M3 ผ่าน:
> alpha −10.79 → −9.40, engaged 83% → 100%) **แต่ตก C1/C2/C7 เพราะแลกด้วย
> drawdown** (15.17% → 16.84%; robust แย่ลง −17.97 → −19.91) เหตุคือ trailing
> คง book ไว้ในตลาดตอน trend → เมื่อยก grid ขึ้นไล่ราคา มันติดอาวุธ BUS ใหม่ที่
> ระดับสูงขึ้นเรื่อย ๆ ถ้า rally กลับตัว BUY เหล่านั้น fill → long ที่ราคาแพง →
> drawdown บาน นี่คือ **แหล่ง drawdown ที่ระบุได้ชัด** จากบันทึก E28

**สมมติฐานระดับกลไก**: drawdown ของ trailing grid มาจาก **inventory ที่สะสม
ไม่จำกัดตอนไล่ราคาขึ้น** ไม่ใช่จาก trailing เอง ถ้า**จำกัด long inventory
ไม่ให้เกินของ grid เดิม** ตอน re-anchor — ยกระดับขึ้นได้ แต่ห้ามเพิ่มจำนวนขา BUY
ที่มีชีวิตเกินจำนวนต่อข้างเดิม — การกลับตัวหลังไล่ราคาจะขาดทุนได้ไม่เกิน grid เดิม
โดย**คงฝั่ง SELL ที่เก็บ alpha ไว้ครบ**

**ตัวแปรเดียวที่เปลี่ยนจาก E28**: `exposureCap` — trailing, trigger, การยก,
fold, ต้นทุน, ทุน, วิธีเลือก geometry, execution mode เหมือน E28 ทั้งหมด
(E29 = E28 + cap; ปิด cap แล้วต้องได้ตัวเลข E28 เป๊ะทุกหลัก)

**หมายเหตุการแก้ก่อนรัน (2026-07-25):** ร่างแรกกำหนด cap ที่ *จำนวนขา BUY* แต่ตรวจ
engine แล้วพบว่า `reAnchor` เรียก `armGrid` ที่ล้าง active แล้ว arm ใหม่ทุกครั้ง →
จำนวนขาถูกจำกัดอยู่แล้ว ไม่ใช่แหล่ง drawdown แหล่งจริงคือ **inventory ที่สะสมข้าม
re-anchor** จึงย้าย cap มาที่ inventory ตรง ๆ ให้ตรงกับสมมติฐาน แก้ก่อนรัน/ก่อนเห็นผล

**พารามิเตอร์ กำหนดตายตัวล่วงหน้า ไม่มีรอบจูน**:
- cap = **ความจุ long สูงสุดของ grid เดิม** = Σ ปริมาณของทุกระดับ BUY ในตอน arm ครั้งแรก
  (ค่านี้คือ geometry ของ grid ตัวเอง ไม่ใช่เลขที่จูน — ไม่มี degree of freedom ให้ fit)
- กติกา: **ไม่ fill BUY ขณะที่ inventory ชน cap** — ไม้ BUY ที่จะดันให้ถือเกินความจุ
  grid เดิมจะยังไม่ fill (order ยังอยู่ที่ราคาเดิมตาม geometry, fill ได้เมื่อ SELL ลด
  inventory ลงมา) จึง**ปิดเพดาน long สูงสุด = cap** โดยไม่ยกเลิก/ไม่บังคับอะไร
  ต่างจาก E27: นี่ไม่ใช่การระงับไม้ที่ราคาค้าง แต่จำกัดปริมาณถือครองสูงสุด
- ฝั่ง SELL ไม่ถูกแตะเลย (แหล่ง alpha ของ trailing)
- ไม่มีการบังคับขาย inventory ที่ถืออยู่; cap จำกัดแค่การ**เพิ่ม** long ใหม่
- ถ้า inventory ไม่เคยชน cap ตลอดการรัน → E29 ต้องได้ตัวเลข E28 เป๊ะ (invariant ตัวแปรเดียว)

**เกณฑ์**: C1–C7 เดิมทั้งหมด (ห้ามลด) **บวก** เกณฑ์เฉพาะกลไกที่วัด *drawdown*:
- **M1 (drawdown ต้องลดจริง)**: mean maxDD ต้อง **< 16.84%** (ต่ำกว่า E28)
  มิฉะนั้น cap ไม่ได้แตะแหล่ง drawdown — กลไกไม่มีผล
- **M2 (robust ต้องดีขึ้น)**: mean robust ต้อง **> −19.91** (ดีกว่า E28) —
  นี่คือเหตุผลทั้งหมดของ E29; ถ้า robust ไม่ดีขึ้น cap ล้มเหลวตามวัตถุประสงค์
- **M3 (ห้ามคืน alpha ทั้งหมด)**: mean alpha ต้องยัง **> −10.79** (ไม่ต่ำกว่า
  baseline E26) มิฉะนั้นแปลว่า cap แน่นจนกลายเป็นถอย E28 ทิ้ง ไม่ใช่ปรับปรุง

**คำตัดสินที่เป็นไปได้ (เขียนก่อนรู้ผล)**:

| ผล | คำตัดสิน |
|---|---|
| ผ่าน C1–C7 | 🟢 มีหลักฐาน OOS ครั้งแรก — ขั้นถัดไป capacity + promotion gate |
| ตก C1–C7 แต่ผ่าน M1+M2+M3 | ⚖️ cap ลด drawdown ได้จริงโดยไม่ทิ้ง alpha — ทิศถูก บันทึกผลบางส่วน ยังไม่ promote |
| ผ่าน M1 แต่ตก M2 | drawdown ลดแต่ robust ไม่ดีขึ้น = cap ตัด alpha มากกว่าที่ลด DD → กลไกนี้ไม่คุ้ม ปิด |
| ตก M1 | ❌ **ปิดสาย exposure-cap** — และ **ห้ามจูนขนาด cap/trigger** ตามบทเรียน E23–E25/E27; ขั้นถัดไปต้องเป็นสมมติฐานคนละกลไก |

## 6d. E30 — Two-sided inventory recycle ตอน re-anchor (ประกาศ 2026-08-31, ก่อนรัน)

> **สถานะ: RUN แล้ว — ⚖️ ผ่าน M1–M5 แต่ตก C1/C2/C7** (2026-08-31)
> engaged คง 100%, DD 16.84% → 16.46%, robust −19.91 → −19.62, alpha −9.40 → −9.86
> กลไกทำงาน (ไม่ disengage แบบ E29) แต่ผลเล็กเกินกว่าจะมี edge · ห้ามจูน target
> รายละเอียดใน `VALIDATION_LOG.md` § E30 · ข้อความเกณฑ์ด้านล่างไม่ถูกแก้หลังรัน
> ที่มาของสมมติฐาน: Minara วิเคราะห์ 43,618 ที่อยู่ Hyperliquid แล้วคัด 12 บัญชีที่
> ทำเงินแบบมีคุณภาพ ([x.com/minara/status/2094395962571755769](https://x.com/minara/status/2094395962571755769))
> กลุ่มหลัก 8/12 ไม่ใช่การทายทิศทาง แต่เป็น **high-turnover two-sided execution**:
> ซื้อ/ขายสมดุล ~49.4/50.6, กำไร ~30.5 bps ต่อกรอสโนชันแนล, คุม inventory
> แล้วเทรดต่อทั้งสองฝั่ง — ไม่ใช่การถือพอร์ตทิศทางเดียว

> ต่อจาก E29 ที่พิสูจน์ว่า **cap แล้วหยุดเทรด** ทำให้ตัวเลข DD สวยขึ้นแบบ tautology
> (engaged 100% → 78%, หลาย fold cycles → 0) ไม่ใช่หลักฐานว่ากลไกมี edge
> Minara Type 1 ทำคนละอย่าง: **recycle inventory แล้วกลับมา quote สองฝั่ง**
> ไม่ใช่ห้ามซื้อแล้วหยุด

**สมมติฐานระดับกลไก**: drawdown ของ trailing มาจาก long ที่สะสมข้าม re-anchor
(บทเรียน E28/E29) แต่การ "ห้ามเพิ่ม" (E29) ทำให้ grid ออกจากตลาด
ถ้าตอน TRAIL_UP re-anchor เรา **ขายส่วนที่เกิน initial inventory ที่ราคาปิด**
(จ่ายต้นทุนไทยครบ) แล้วค่อย arm grid ใหม่รอบราคา — inventory กลับไปที่ท่า 50/50
เดิม แล้วกลับมาเทรดได้ทั้งสองฝั่ง นี่คือ "reducing inventory after short
directional moves" ที่ Minara วัดได้จาก fills ของกลุ่ม Type 1
ต่างจาก E29: นี่เป็นการ **recycle จริง** ไม่ใช่ cap แล้วรอ

**ตัวแปรเดียวที่เปลี่ยนจาก E28**: `inventoryRecycle` — trailing, trigger, การยก,
fold, ต้นทุน, ทุน, วิธีเลือก geometry, execution mode เหมือน E28 ทั้งหมด
(E30 = E28 + recycle; ปิด recycle แล้วต้องได้ตัวเลข E28 เป๊ะทุกหลัก)
**ไม่เปิดร่วมกับ `exposureCap`** — นั่นจะเป็นสองตัวแปร

**พารามิเตอร์ กำหนดตายตัวล่วงหน้า ไม่มีรอบจูน**:
- target = **`initialInventory`** ของโปรโตคอล (ท่า 50/50 หุ้นตั้งต้น) —
  ค่านี้คือ geometry/ท่าของกริดเอง ไม่ใช่เลขที่จูน
- กติกา: ตอน re-anchor ถ้า inventory > target ให้ขายส่วนเกินลงมาที่ target
  ที่ราคาปิด (board-lot, ค่าธรรมเนียม+สลิปครบ) แล้วค่อยยก ladder / arm ใหม่
- ถ้า inventory ไม่เกิน target → ไม่ขาย → ต้องได้ตัวเลข E28 เป๊ะ (invariant ตัวแปรเดียว)
- ไม้ recycle **ไม่นับเป็น grid cycle** (ไม่ใช่คู่ซื้อ-ขายบนเส้นกริด) แต่เป็น
  turnover จริง จึงถูกบันทึกเป็น fill เพื่อวัด fingerprint
- ฝั่ง SELL ของกริดไม่ถูกแตะนอกจังหวะ re-anchor; ไม่มีการบังคับขายถ้ายังไม่ยกกริด
- **ห้ามจูน target/สัดส่วน** ตามบทเรียน E23–E25/E27/E29

**เกณฑ์**: C1–C7 เดิมทั้งหมด (ห้ามลด) **บวก** เกณฑ์เฉพาะกลไกที่วัด *recycle ไม่ใช่ disengage*:
- **M1 (ห้ามหยุดเทรด)**: mean engaged ต้อง **= 100%** (เท่า E28, สูงกว่า E29 ที่ 78%)
  มิฉะนั้น recycle กลายเป็น cap ตัวใหม่ที่ดันให้ออกจากตลาด — กลไกผิดแบบเดียวกับ E29
- **M2 (drawdown ต้องลดจริง)**: mean maxDD ต้อง **< 16.84%** (ต่ำกว่า E28)
  มิฉะนั้นการ flatten ไม่ได้แตะแหล่ง long-inventory
- **M3 (ห้ามคืน alpha ทั้งหมด)**: mean alpha ต้องยัง **> −10.79** (ไม่ต่ำกว่า E26)
- **M4 (robust ต้องดีขึ้นจาก E28)**: mean robust ต้อง **> −19.91**
  มิฉะนั้นค่าธรรมเนียมตอน recycle แพงกว่าที่ลด DD
- **M5 (decomposition — บทเรียน E29)**: ใน fold ที่ตัวเลขขยับจาก E28
  **ห้ามให้ผลดีถูกขับด้วย cycles → 0** ถ้า fold ที่เปลี่ยนแล้ว cycles=0
  เป็นตัวดึง mean หลัก ให้บันทึกว่ากลไกไม่ผ่านแม้ M1–M4 ผ่านบนค่าเฉลี่ย

**คำตัดสินที่เป็นไปได้ (เขียนก่อนรู้ผล)**:

| ผล | คำตัดสิน |
|---|---|
| ผ่าน C1–C7 | 🟢 มีหลักฐาน OOS ครั้งแรก — ขั้นถัดไป capacity + promotion gate |
| ตก C1–C7 แต่ผ่าน M1+M2+M3+M4 และ M5 ไม่ล้ม | ⚖️ recycle ลด DD ได้โดยยังเทรดอยู่ — ทิศถูก บันทึกผลบางส่วน ยังไม่ promote |
| ตก M1 | ❌ **ปิดสาย inventory-recycle** — กลไก disengage แบบเดียวกับ E29; ห้ามจูน target |
| ผ่าน M1 แต่ตก M2 หรือ M4 | flatten ไม่คุ้ม (ไม่ลด DD หรือ robust แย่ลงเพราะค่าธรรมเนียม) — ปิดสาย ห้ามจูน |
