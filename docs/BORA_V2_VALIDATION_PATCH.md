แก้สามจุดในส่วนตรวจสอบของ `BORA_V2_Development_Spec.md` · เขียนให้วางทับได้เลย

จำนวนเท่ากัน 16 จาก 20 seeds ปัญหาไม่ใช่การจูนผิด แต่เป็นช่องโหว่เชิงโครงสร้าง
ของเกณฑ์เอง

## PATCH 1 — §22 Control Group: เพิ่ม Group C

### ปัญหา

Group B ("Extreme Sell + No Absorption") เก็บสัญญาณไว้เกือบทั้งหมด ส่วน Group A
เก็บไว้ไม่กี่ตัว **เมื่อ baseline ติดลบ การเทียบ A กับ B จึงกลายเป็นการเทียบ
"เทรดน้อย" กับ "เทรดมาก" ไม่ใช่การเทียบ "มี absorption" กับ "ไม่มี"**

ใน E59: Group A เหลือ 3 ไม้จาก 221 (0.7%) · Group B เก็บไว้ 99% · A ชนะ B
ด้วยระยะ **54 R** ทั้งที่ A ไม่มี edge อะไรเลย

### แก้เป็น

```
Group A   Extreme Sell + Absorption
Group B   Extreme Sell + No Absorption          (control เดิม)
Group C   สุ่มเก็บสัญญาณที่สัดส่วนเท่ากับ A พอดี   ← เพิ่มใหม่
          ทำซ้ำ >= 20 seeds
```

**เกณฑ์ผ่าน**: `A > B` **และ** `A > p90 ของ C`

> **Group B ตอบว่า "absorption ดีกว่าไม่มี absorption ไหม"
> Group C ตอบว่า "absorption ดีกว่าการทิ้งไม้แบบสุ่มจำนวนเท่ากันไหม"
> คำถามที่สองคือคำถามที่แยก edge จริงออกจากการเทรดน้อยลง**

ถ้า A ไม่ชนะ C → **นิยาม absorption ไม่มีข้อมูลอยู่ในนั้น** ต่อให้ชนะ B ขาดแค่ไหน

กฎนี้ใช้กับ **ทุกตัวกรองในสเปก** ไม่ใช่แค่ absorption — Location Score (§14),
Regime gate (§15), BORA Score threshold (§32) ทุกตัวคือตัวกรองที่ลดจำนวนไม้
ทุกตัวต้องผ่าน Group C

## PATCH 2 — §23 Parameter Matrix: เพิ่มพื้นขั้นต่ำของจำนวนไม้

### ปัญหา

`Delta Z ∈ {1.5, 2, 2.5, 3}` × `percentile ∈ {90, 95, 97, 99}` ยิ่งเข้มยิ่งเหลือ
ไม้น้อย และสเปกไม่มีเกณฑ์ขั้นต่ำ ทำให้ **แขนที่เหลือ 2 ไม้ผ่าน §22/§23/§25 ได้**

แย่กว่านั้น: §23 บอกให้หา *stable region* แต่ **ยิ่ง threshold สูง ยิ่งเทรดน้อย
ยิ่งดู "เสถียร"** เพราะไม่มีอะไรให้แกว่ง ใน E59 แขน M1 ชนะ baseline **3 จาก 3
ค่า Zt** ทั้งที่เหลือ 9, 3 และ 2 ไม้ตามลำดับ

### แก้เป็น

```
เกณฑ์คัดกรองก่อนอ่านผลใด ๆ (ประกาศก่อนรัน):

  ไม้ < 30                 -> NO VERDICT  รายงานว่า "ตัวอย่างไม่พอ" เท่านั้น
  ไม้ >= 30                -> อ่านผลได้
  duty cycle < 5%          -> ต้องรายงาน duty ติดกับตัวเลขทุกครั้ง

stable region ต้องนิยามด้วย "ช่องข้างเคียงที่ผ่านพื้นขั้นต่ำ"
ไม่ใช่ด้วยค่าที่ดีที่สุด
```

**ห้ามใช้ผลจากแขนที่ต่ำกว่าพื้นเป็นหลักฐานสนับสนุน** แม้ตัวเลขจะสวย

## PATCH 3 — §38 Definition of Success: เพิ่มข้อสุดท้าย

### ปัญหา

เกณฑ์ปัจจุบัน (Positive Expectancy, PF > 1, DD รับได้, Walk-forward เสถียร,
หลาย regime, Parameter Stability, Monte Carlo, Paper ≈ Backtest) **ครบทุกข้อ
ยกเว้นข้อที่ฆ่ากลยุทธ์ได้จริงที่สุด**

กลยุทธ์ผ่านทั้งแปดข้อได้ พร้อมกับแพ้การซื้อแล้วถือเฉย ๆ

### แก้เป็น เพิ่มข้อที่เก้า

```
        +
ชนะการถือเฉย ๆ ที่ความเสี่ยงเท่ากัน
วัดเป็นการกระจายตัว ไม่ใช่เส้นทางเดียว
```

**วิธีวัดที่ต้องใช้**:

1. ปรับ risk/ไม้ ให้ maxDD ของกลยุทธ์ **เท่ากับ** maxDD ของการถือเฉย ๆ
   บนหน้าต่างเดียวกัน คาลิเบรตครั้งเดียว แล้วตรึงไว้
2. **paired block bootstrap** — สับลำดับวันเป็นบล็อก (เช่น 20 วัน) แล้วใช้
   **ลำดับบล็อกเดียวกัน**กับทั้งสองฝั่ง ทำ >= 500 เส้น
3. นับสัดส่วนเส้นที่กลยุทธ์ชนะด้าน **ความมั่งคั่งปลายทาง**
4. **เกณฑ์: ชนะ >= 60% ของเส้น** (ประกาศก่อนรัน ห้ามปรับหลังเห็นผล)
5. ไม่คิดค่าธรรมเนียมให้การถือเฉย ๆ (ให้แต้มต่อฝั่งที่ไม่ทำอะไร)

**ทำไมต้องเป็นการกระจายตัว**: บนเส้นทางจริง กลยุทธ์หนึ่งเคยให้ +107% เทียบ
buy&hold +49% ที่ DD เท่ากัน — ดูเหมือนชนะสองเท่า พอสับประวัติศาสตร์ 500 ครั้ง
**ชนะแค่ 57%** ⇒ ความได้เปรียบนั้นคือลำดับเหตุการณ์ที่บังเอิญ ไม่ใช่คุณสมบัติ
ของกลยุทธ์ · **การเทียบเส้นทางเดียวให้คำตอบผิดเครื่องหมายได้**

## สิ่งที่สเปก BORA ทำได้ดีอยู่แล้ว — อย่าแก้

- **§20 Don't Trade the Bubble** — "Big Buy ≠ Long" คือหลักที่ถูกต้อง
- **§24 Walk-Forward** — แบ่ง train/validate/test ชัด และห้ามใช้ test เลือกพารามิเตอร์
- **§28 Cost Model** — stress 1.5×/2× และ "ถ้าตายเมื่อ cost เพิ่มนิดเดียว = edge ไม่แข็ง"
- **§31 Monte Carlo** — 1,000–10,000 เส้น พร้อม Risk of Ruin
- **§4 INVALID Policy** — ห้าม interpolate ห้ามสร้าง synthetic delta ห้ามย้าย timestamp
- **§33 Meta Labeling** — ไม่ให้ ML เดา up/down แต่ให้ทำนาย TP-before-SL
- **§35** — "LLM ไม่ควรมีสิทธิ์ override Risk Gate"

## สิ่งที่ควรเลื่อนออกไปจนกว่าจะผ่านด่าน 1–9

**§32 BORA Score** — 8 องค์ประกอบถ่วงน้ำหนักพร้อม threshold 60/70/80 คือการรวม
สมมติฐานที่ยังไม่ผ่านทีละตัวเข้าด้วยกัน แล้วจูนน้ำหนัก · ต้องพิสูจน์แต่ละองค์ประกอบ
ผ่านด่าน 3 ก่อน จึงค่อยรวม ไม่ใช่รวมก่อนแล้วจูน
