## 0. ทำไมถึงเป็นการทดลองนี้ ไม่ใช่ variant ที่ N ของ entry/exit

**E34 K6 คือข้อค้นพบเชิงบวกอันเดียวใน ledger ทั้งเล่ม**: ตัวกรองเทรนด์ SMA-200
แบบเข้า/ออก **ชนะ constant-mix ที่ถือ exposure เฉลี่ยเท่ากันแบบไม่มีสัญญาณเลย**
robust **−0.139 vs −0.260** (ห่าง **0.121**) บน BTC รายวัน 12 หน้าต่าง

แปลว่า **ตัวกรองมีข้อมูลจริง** — ไม่ได้แค่ "ถือน้อยลง" แต่รู้ว่าควรถือ*เมื่อไหร่*

**แต่รูปแบบเข้า/ออกทิ้งข้อมูลไปครึ่งหนึ่ง**: มันปฏิบัติกับ "อยู่เหนือ SMA-200 อยู่ 1%"
เหมือนกับ "อยู่เหนือ 40%" ทั้งที่เป็นคนละสถานการณ์

> **สมมติฐานเชิงกลไก: ถ้าข้อมูลในตัวกรองเป็นแบบไล่ระดับ การถือแบบไล่ระดับตาม
> ความแรงของเทรนด์ ควรชนะการถือแบบเข้า/ออก ที่ exposure เฉลี่ยเท่ากัน**

เป็นแกน **sizing/exposure** ซึ่ง E30–E38 ไม่เคยแตะ (ทุกอันเป็นแกน timing หรือ
leverage ซึ่งถูกเผาไปหมดแล้ว)

## 1. ข้อกล่าวอ้างย่อยที่วัดได้ก่อนดูผลตอบแทน (P1)

วัด **ก่อน** รัน backtest และรายงานไม่ว่าผลจะออกทางไหน:

> **P1 — ผลตอบแทนล่วงหน้า 21 แท่ง เรียงตามเดไซล์ของความแรงเทรนด์ ต้องเพิ่มขึ้น
> แบบมีทิศทาง**: Spearman rank correlation ระหว่างเดไซล์กับผลตอบแทนเฉลี่ย **> 0**
> และชนะ **permutation test 1,000 ครั้ง ที่เปอร์เซ็นไทล์ ≥ 90%**

**ถ้า P1 ไม่ผ่าน → กลไกตั้งอยู่บนสมมติฐานที่ผิด (ความแรงไม่มีข้อมูลเพิ่มจากทิศทาง)
รายงานแล้วหยุด ห้ามจูนต่อ** (บทเรียน E27/E34)

## 3. นิยามความแรงเทรนด์ (ล็อก ห้ามเพิ่มหลังเห็นผล)

`raw[i] = close[i] / SMA200[i] − 1` (causal, NaN ระหว่าง warm-up)

**ความแรง = percentile rank ของ `raw[i]` เทียบกับ `raw` ย้อนหลัง 252 แท่ง**
→ อยู่ใน [0, 1] และ **ค่าเฉลี่ยระยะยาว ≈ 0.5 โดยโครงสร้าง**

ใช้ percentile rank ไม่ใช่ค่าดิบ เพราะค่าดิบขึ้นกับความผันผวนของยุคนั้น ๆ —
เป็นตัวตรวจจับเดียวกับที่ E14 validate ไว้แล้ว **ไม่ใช่พารามิเตอร์ใหม่**

## 4. ผู้เข้าแข่งขัน (5 แขน ประกาศครบ ไม่มีเพิ่มภายหลัง)

| id | น้ำหนักเป้าหมาย | บทบาท |
|---|---|---|
| A0 | 1.0 เสมอ | buy & hold — control |
| A1 | 1.0 เมื่อเหนือ SMA-200, 0 เมื่อต่ำกว่า | **เข้า/ออก — ทำซ้ำ E34 C2 และเป็นตัวเทียบหลัก** |
| **A2** | **= ความแรง (percentile rank) ใน [0,1]** | **ไล่ระดับ — ข้อกล่าวอ้างที่ทดสอบ** |
| A3 | inverse-vol: `min(0.40 / realized_vol, 1)` | **control: เป็นข้อมูลเทรนด์ หรือแค่ปรับตามความเสี่ยง** |
| A4 | คงที่ = exposure เฉลี่ยที่ A1 ทำได้จริง | **control: เป็นสัญญาณอะไรก็ได้ หรือแค่ถือน้อยลง** (K6 ของ E34) |

A3 ใช้ `target_vol = 0.40`/ปี, `realized_vol` = ส่วนเบี่ยงเบน 20 แท่ง — ค่าเดียวกับ
`VolTargetSma` ที่มีอยู่แล้วในโค้ด **ไม่ได้ fit กับข้อมูลชุดนี้**

**ทุกแขนต้องรายงาน exposure เฉลี่ยที่ทำได้จริง** ถ้า A2 กับ A1 ต่างกันเกิน
**5 จุดเปอร์เซ็นต์** ให้ถือว่าการเทียบมี confound และ **ต้องรายงานแบบนั้น**
พร้อมรันแขนเสริม **A2s** = A2 ปรับสเกลให้ exposure เท่า A1 โดยคำนวณสเกล
**จากช่วง warm-up เท่านั้น** (causal)

## 5. เกณฑ์ตัดสิน (ไม่ลดจากเกณฑ์โปรเจกต์)

robust = `return − 2 × maxDD` · เฉลี่ยข้าม 12 หน้าต่าง OOS

| id | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| **R1** | P1 — ความแรงเรียงตามผลตอบแทนจริง | Spearman > 0 และ permutation ≥ 90% |
| **R2** | **A2 mean robust > A1** | **นี่คือคำถามหลักของการทดลอง** |
| R3 | A2 mean robust > 0 | |
| R4 | A2 > A4 (constant-mix exposure-matched) | ทำซ้ำ K6 |
| R5 | A2 > A3 (inverse-vol) | ข้อมูลมาจากเทรนด์ ไม่ใช่แค่การปรับความเสี่ยง |
| R6 | A2 > A0 (buy & hold) | |
| R7 | held-out ETH **และ** SOL: A2 robust > 0 | ประเมินเฉพาะเมื่อ R2–R6 ผ่าน |

**Promote ต่อเมื่อ R2–R7 ผ่านครบ** · ธรรมนูญห้ามเทรดจริงอยู่แล้วไม่ว่าผลใด

## 6. ตารางการตัดสินใจ (เขียนก่อนเห็นผล)

| ผลลัพธ์ | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| R1 ตก | ความแรงไม่มีข้อมูลเพิ่มจากทิศทาง | **หยุด** รายงาน · แกน sizing ปิดสำหรับตัวกรองนี้ |
| **R2 ผ่าน แต่ R3 ตก** | **ไล่ระดับดีกว่าเข้า/ออกจริง แต่ยังไม่พอผ่านเกต** | ⚖️ **นี่คือผลที่คาดไว้มากที่สุด** — บันทึกเป็นความคืบหน้าเชิงกลไก ไม่ promote |
| R2 ตก | ข้อมูลเป็นแบบทิศทางล้วน ไม่ไล่ระดับ | ⚖️ เข้า/ออกคือรูปแบบที่ถูกแล้ว · แกนนี้ปิด |
