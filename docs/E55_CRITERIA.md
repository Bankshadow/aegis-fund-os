## 0. ที่มา และสิ่งที่ E55 **ไม่ใช่**

ผู้ใช้ส่งสเปกที่ล็อกแล้ว (`final_logic.md`) มาให้ audit เทียบกับโค้ดในรีโป ผล audit
พบช่องว่าง 4 จุด E55 คือการ**ปิดช่องว่างทั้งสี่ด้วยการวัด** ไม่ใช่ด้วยการเชื่อสเปก

**ตัวเลขในสเปกที่ยังไม่มีหลักฐานในรีโปนี้**: `S017 vs S003 portR +55.3 vs +49.1`,
`minFold +9.8 vs +6.7`, `2025–26 CAGR +66% / MaxDD −22%` — ทั้งหมดมาจากแล็บภายนอก
E55 **ไม่รับตัวเลขเหล่านี้เป็นหลักฐาน** และไม่ใช้มันเป็นเป้าให้โค้ดวิ่งเข้าหา
สิ่งเดียวที่ยืมมาคือ**กฎ** (streak 4 → ข้าม 2) ซึ่งจะถูกทดสอบเหมือนผู้สมัครหน้าใหม่ทุกราย

**E55 ไม่ใช่การจูน** ไม่มีการเลือกค่าที่ดีที่สุดให้ผู้ใช้ · ไม่มี promote ·
ไม่มีคำสั่งจริง · ไม่ลดเกณฑ์ ValidationGate

> **บทเรียนที่บังคับใช้กับ E55**: E48 พิสูจน์แล้วว่า overlay ที่ "ผ่าน" บนหน้าต่างเดียว
> แพ้ตัวสุ่มที่ duty cycle เท่ากัน · E53 พิสูจน์ว่าการเลือกพารามิเตอร์แพ้การตรึงมัน
> ดังนั้น **S017 ต้องผ่าน placebo ก่อน จึงจะถือว่ามีกลไก**

## 1. หน่วยที่ต้องสร้าง (ล็อกก่อนรัน)

`run_portfolio()` — ไดรเวอร์ที่รัน SOL + LINK **ในลูปเดียว** บนแกนวันที่รวม
เหตุผลที่ post-process จาก trade list เดิมไม่ได้: การข้ามสัญญาณทำให้เหรียญนั้น
**ว่างเร็วขึ้น** สัญญาณถัดไปที่เดิมถูกบล็อกด้วย "มี position อยู่" จึงกลายเป็นเข้าได้
ลำดับเทรดทั้งเส้นเปลี่ยน ไม่ใช่แค่ตัดบางไม้ออก

**ความกำกวมที่ต้องประกาศคำตอบไว้ก่อน** (สเปกไม่ได้ระบุ):

| กรณี | คำตอบที่ล็อก |
|---|---|
| ในหนึ่งแท่ง จัดการ position ก่อน หรือรับสัญญาณก่อน | **จัดการก่อน** (เหมือน `run_symbol` เดิมทุกประการ) เหรียญที่ปิดในแท่งนั้นรับสัญญาณใหม่ในแท่งเดียวกันได้ |
| สองเหรียญปิดวันเดียวกัน — นับ streak เรียงยังไง | เรียงตาม **exit_date แล้วตามชื่อเหรียญ (A→Z)** |
| สองเหรียญให้สัญญาณวันเดียวกัน แต่ `cool_left = 1` — ใครโดนข้าม | เรียงตาม **ชื่อเหรียญ (A→Z)** ⇒ LINK ถูกพิจารณาก่อน SOL |
| สัญญาณที่ถูก skip ด้วย "มี position อยู่แล้ว" | **ไม่นับ** เป็นการใช้โควตา cooldown (ไม่ลด `cool_left`) — ยังไม่ถือว่าเป็น "new signal" ตาม §5 |
| สัญญาณที่ถูก cooldown ข้าม แต่ถ้าไม่ถูกข้ามก็จะถูกปัดทิ้งด้วย `R > 3 ATR` อยู่ดี | **ยังนับว่าใช้โควตา** — สเปก §5 วางการเช็ค cooldown ไว้ **ก่อน** การเข้าไม้ จึงลด `cool_left` ตามลำดับที่เขียนไว้ |
| duty cycle ที่ placebo ต้องเลียนแบบ | = สัญญาณที่ถูกข้าม ÷ สัญญาณที่**มาถึงประตู cooldown** (ไม่นับสัญญาณที่ถูกบล็อกด้วย position ที่เปิดอยู่) |
| เทรดที่ปิดด้วย EOD (จบข้อมูล) | นับ P&L ปกติ แต่ไม่มีสัญญาณเหลือให้ cooldown มีผล |

Entry/stop/target/fee/warmup ทั้งหมด**ห้ามแตะ** — ใช้ `plan_trade()` และ
`close_trade()` เดิมทั้งดุ้น

## 2. Harness — ไม่ผ่าน = หยุด

| id | เงื่อนไข | เกณฑ์ |
|---|---|---|

## 3. คำถาม A — S017 cooldown 4/2 มีกลไกจริงไหม

ทุกข้อรันบนเต็มประวัติ (2017-11-09 → 2026-08-12) หน่วยเป็น R (ยังไม่ทบต้น)

| id | การทดสอบ | เกณฑ์ผ่าน |
|---|---|---|
| **A1** | portR ของ S017 (streak 4 → ข้าม 2) เทียบ S003 | S017 > S003 |
| **A2** | fold ครึ่งปีตาม **exit_date** — fold ที่แย่ที่สุด | minFold ของ S017 ≥ minFold ของ S003 |
| **A3** | **placebo**: ข้ามสัญญาณแบบสุ่มที่ duty cycle เท่ากับที่ S017 ข้ามจริง × **20 seeds** (seed 7000+i) | portR ของ S017 > **p90** ของ placebo |
| **A4** | **ย่านพารามิเตอร์**: streak ∈ {3,4,5} × skip ∈ {1,2,3} = 9 ช่อง | รายงานครบ 9 ช่อง · ผ่านเมื่อ ≥ 5/9 ช่อง > S003 |
| **A5** | **ต่อเหรียญ** — S017 ต้องชนะ S003 ทั้ง SOL และ LINK | ชนะทั้งสอง |
| **A6** | **sl_first** (intrabar มองโลกร้าย) | S017 > S003 ภายใต้ sl_first ด้วย |

**รายงานเสมอ ไม่ว่าผลออกทางไหน**: ตัวแปรที่สเปกบอกว่า "เคยพัง" —
streak ต่อเหรียญ (แทนที่จะรวมพอร์ต) และ pause หลังแพ้ 2 — ต้องรันและรายงานด้วย
ถ้ามันดีกว่า 4/2 ให้บอกตรง ๆ

**A3 คือข้อชี้ขาด** ถ้า A3 ตก แปลว่าประโยชน์ของ cooldown คือ "เทรดน้อยลง" เฉย ๆ
ไม่ใช่ "หลบช่วงแพ้เป็นกระจุก" → ต้องรายงานว่า S017 **ไม่มีกลไก** และคำแนะนำคือ
ลด risk ต่อไม้แทน (บทเรียนเดียวกับ E47/E48)

## 4. คำถาม B — risk 4% ของ equity รวม แปลว่าอะไร

ใช้ **วิธีเดียวกับ E49 ทุกประการ** (moving-block bootstrap บล็อก 10 ไม้ ×
500 resamples seed 5000+i) แต่รันบน**ลำดับเทรดของ S017** (ถ้า A ผ่าน) และ
ของ S003 (เสมอ) เพื่อเทียบ

| id | รายการ | รายงานเมื่อ |
|---|---|---|
| **B1** | ตาราง 9 ระดับ (0.5–10%) เหมือน E49: CAGR/DD บน IS, OOS, เต็มประวัติ | ทุกระดับเสมอ |
| **B2** | ที่ **4%**: p90 DD, p95, worst, สัดส่วนเส้นทางที่ DD > 80% | รายงานตรง ๆ |
| **B3** | **ความทนต่อ DD ที่ 4% เรียกร้องจริง** = p90 DD ที่ 4% (ปัดขึ้น 5%) | รายงานเป็นข้อสรุปหลักของ B |
| **B4** | ตารางแปลง tolerance → risk ด้วย**กฎเดิมของ E49** (สูงสุดที่ p90 DD ≤ tolerance) ที่ tolerance {20,30,40,50,60,70}% | รายงานเต็ม |

**ห้ามเลือกแทนผู้ใช้** E55 รายงานว่า 4% ซื้อ CAGR เท่าไรด้วยราคา DD เท่าไร
แล้วจบ · ถ้า p90 DD ที่ 4% เกิน 50% ต้องเขียนคำเตือนไว้ติดกับตัวเลขทุกครั้ง

**ข้อจำกัดที่ต้องเปิดเผยเหมือน E49**: bootstrap รันทีละไม้ไม่มีการถือซ้อน จึงต้อง
เทียบกับ `sequential reference` ของลำดับจริง ไม่ใช่เลข overlap · และ bootstrap
สุ่มจาก**อดีตเท่านั้น** ระบอบที่ไม่เคยเกิดไม่อยู่ในนั้น

## 5. คำถาม C — overlay ตามสเปกจริง (clamp 4.0, expanding σ_ref)

E47 รัน overlay ด้วย clamp `[0.25, 2.0]` และ `σ_ref` = มัธยฐานคงที่ของช่วง IS
สเปกเขียนว่า clamp `~[0.25, 4]` และ `σ_ref` = **expanding median** (มัธยฐานของ σ
ทั้งหมดที่เห็นมาจนถึงไม้นั้น — ไม่มี look-ahead)

**E47 จะไม่ถูกแก้** เพราะเป็นการทดลองที่ log แล้ว และ E48/E49 import ค่าคงที่
harness จากมัน การแก้ย้อนหลังจะทำให้ผลที่บันทึกไว้ 3 รายการเป็นโมฆะ
overlay ตามสเปกจึงถูกสร้างใหม่ใน E55 และเทียบกับ flat ด้วยวิธีของ E47

| id | การทดสอบ | เกณฑ์ผ่าน |
|---|---|---|
| **C1** | คาลิเบรต base risk ของทั้ง flat และ overlay บน **IS ให้ maxDD = 45%** เท่ากัน แล้วอ่าน OOS ครั้งเดียว | overlay OOS CAGR > flat |
| **C2** | ที่ DD เท่ากันบน IS | overlay OOS maxDD ≤ flat |
| **C3** | **placebo** — สุ่ม scale จากการสับ (permute) ลำดับ `scale` ที่ overlay ใช้จริง × 20 seeds (seed 8000+i) | overlay > p90 ของ placebo |
| **C4** | ย่าน exponent γ ∈ {−1.0, −0.5, 0.0} และ clamp สูงสุด ∈ {2, 4} | รายงานครบ 6 ช่อง |

C1+C2 ผ่านแต่ C3 ตก = "overlay ได้ประโยชน์จากการเปลี่ยนขนาดไม้เฉย ๆ ไม่ใช่จาก
การอ่าน vol" → รายงานว่า overlay **ยังคงเป็น optional และไม่มีหลักฐานสนับสนุน**
ตรงกับที่สเปกเองเขียนว่า "not required"

## 6. คำถาม D — กฎ BE-bar

โค้ดปัจจุบัน (`strat_trap.py` L185–190) มีกฎที่ `final_logic.md` **ไม่ได้เขียนไว้**:
แท่งที่แตะ TP2 แล้วเลื่อน stop มา BE จะ**ไม่ถูกเช็ค stop ในแท่งเดียวกัน**ภายใต้
`tp_first` กฎนี้มาจาก `s003_agent_spec.md` §5.7 ฉบับก่อน และถูก pin ด้วยเทสต์

| id | การทดสอบ | รายงาน |
|---|---|---|
| **D1** | รันสองแบบ: (ก) โค้ดปัจจุบัน (ข) อ่านสเปกตามตัวอักษร — แท่งที่ arm BE **ถูก stop ที่ BE ได้** | portR ทั้งสองแบบ + จำนวนไม้ที่ผลต่างกัน |
| **D2** | ช่องว่าง `|portR(ก) − portR(ข)| / |portR(ก)|` | รายงานเป็น % |

**กฎตัดสินที่ประกาศไว้ล่วงหน้า**:

| ผล D2 | อ่านว่า | ทำอะไรต่อ |
|---|---|---|
| ≤ 5% | กฎนี้ไม่สำคัญเชิงตัวเลข | คงโค้ดเดิม · เพิ่มประโยคใน `final_logic.md` §4 ให้ระบุกฎนี้ชัด |
| > 5% | กฎนี้เป็น **ตัวเลือกออกแบบที่มีผลจริง** | คงโค้ดเดิม (เพราะ E44–E51 ทุกผลอิงมัน) · **บังคับ**ให้ `final_logic.md` §4 เขียนกฎนี้ · และให้แบบ (ข) เป็น **error bar ที่ต้องรายงานคู่กันทุกครั้ง** เหมือน `sl_first` |

ไม่ว่ากรณีไหน **ห้ามแก้โค้ดหลักและห้ามแก้เทสต์ที่ pin ไว้** — การเปลี่ยนกฎนี้จะทำให้
ผลที่ log ไว้ตั้งแต่ E44 เป็นโมฆะทั้งชุด และนั่นคือราคาที่ไม่คุ้มกับความคลุมเครือ 1 ประโยค

## 8. สิ่งที่จะไม่ทำ

- ไม่แก้ entry / stop / target / fee / warmup — **สเปก §1–§4 ห้ามแตะ**
- ไม่แก้ `e47/e48/e49` ที่ log ไปแล้ว · ไม่แก้เทสต์เดิมให้ผ่าน
- ไม่เพิ่มการทดสอบหลังเห็นผล · ไม่เพิ่มค่าในย่านพารามิเตอร์หลังเห็นผล
- ไม่ใช้ตัวเลขจาก `final_logic.md` §8 เป็นเป้าหรือเป็นหลักฐาน
- ไม่ promote · ไม่มีคำสั่งจริง · ไม่ให้คำแนะนำการลงทุนรายบุคคล
- ไม่รายงานเฉพาะช่องที่ผ่าน — **ทุกช่อง ทุกย่าน เสมอ**
